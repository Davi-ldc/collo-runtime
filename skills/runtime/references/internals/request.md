# The request path

This document follows one HTTP/2 request through the server: the ingress lane that accepts its connection, admission into the pool of its worker definition, the dispatch to a worker, the response, the finish and the records the request leaves, then the failure domains, the deadline and every named limit on the way. The lane's code is in `runtime/src/server/ingress/` with its `runner/` and `http2/` directories, the pool, the worker records and their request tables are in `runtime/src/server/supervisor/`, the access records in `runtime/src/server/analytics/`, and their `//!` headers own the mechanics; [scheduler.md](scheduler.md) covers the pool, the launcher and the reaper. A reference such as `dispatch.zig:dispatchWithHead` names a file and a symbol in it. A bare file name is in one of those directories, a name two of them share carries its directory (`runner/root.zig`, `http2/connection.zig`), and any other path is relative to `runtime/src/`.

## The lane thread

The server runs one lane per listener, each on its own thread pinned to the CPU the lane plan gave it (`service.zig:Service.init`, `runner/root.zig:LaneWorker.threadMain`). Once its loop runs, the lane thread alone changes its connection, request and stream slabs, its deadline wheel and connection deadline heap, its worker registrations, its read buffer and its HPACK scratch. Other threads reach a lane only by posting to its command queue under `runtime_mutex` (`runner/root.zig:LaneWorker.post`), by raising one of its wake bits under the same mutex, which writes the queue's eventfd only when the bit was clear (`runner/root.zig:LaneWorker.raiseWake`, `wake`), by reading its counters under `counters_mutex` or its atomic `lane_state`, and, for the metrics thread, by draining its access records (`runner/root.zig:LaneWorker.access_ring`).

A lane's tables are fault-in slabs (`slab.zig:FaultInSlab`): each reserves its capacity as address space with MAP_NORESERVE and touches an entry only when it first hands it out, from a high-water mark and then from a LIFO free stack, so a lane costs memory as far as it has been used, not as far as it could be. Every entry carries a generation that never repeats, which is what a key names along with the index, so a key that outlives its entry reads as stale.

Every event source of a lane completes on the lane's one io_uring (`ring_driver.zig:run`), and each completion runs one handler of `fault.zig:loop_handlers`:

| Source | Event | Handler |
| --- | --- | --- |
| the listener's multishot accept | an accept tag (`accept.zig:unpackAcceptUserData`) | `accept_flow.zig:handleAcceptCqe` |
| the command queue's eventfd, for commands and wake bits | `command` (`event_sources.zig:EventKind`) | `command_flow.zig:handleCommands` |
| the lane's one deadline timerfd | `deadline_timer` | `deadline_driver.zig:handleDeadlineTimer` |
| a client socket, one one-shot poll per interest | `connection_read`, `connection_write` | `ring_driver.zig:handleConnectionReadable`, `handleConnectionWritable` |
| a worker the lane reads: its control socket, completion eventfd and pidfd | `worker_control`, `worker_ring_credit`, `worker_pidfd` | `ring_driver.zig:handleWorkerControlReadable`, `request_body.zig:handleWorkerRingCredit`, `ring_driver.zig:handleWorkerPidfd` |
| a worker the lane sends to, while one of its sends waits for room in the socket | `worker_control_writable` | `ring_driver.zig:handleWorkerControlWritable` |

A pass of the loop (`ring_driver.zig:runPass`) renews the lane's egress lease when the gateway generation moved, re-arms the accept when it is due, takes up to 64 completions and runs their handlers, then runs the queued work: each connection a handler queued for a turn and the worker faults deferred out of stream handlers (`ring_driver.zig:runQueuedWork`). Handlers only prepare submissions: the pass ends in one `io_uring_enter` that submits them all, and waits for a completion unless the pass left work queued that no completion announces, a connection's turn or a deferred worker fault; a poll armed on a ready descriptor completes inside that submission, and a pending completion ends the wait at once (`ring_driver.zig:runPass`). Only a pass that fills the ring's 256 submission entries enters early, and every enter is counted (`event_sources.zig:LaneRing`), so the lane's counters show `ring_enters` against `loop_passes`. A completion whose connection or registration moved on since its poll was armed carries an older generation and is counted as stale (`ring_driver.zig:dispatchCqe`, `workerPollReady`).

An accepted socket takes a connection slot and holds it until it closes (`accept_flow.zig:startConnection`), whichever arming of the accept delivered it; a socket that finds the lane's 4096 slots taken, or cannot be set up, closes alone as `connection_limit` or `setup_failed` (`fault.zig:classifyAccept`). A connection's slot is about 1.2 KiB: its streams live in the lane's stream slab, and every socket read of every connection goes into the lane's one read buffer, a frame header and the largest frame long (`http2/lane_resources.zig:LaneResources`). The lane handles every byte of a read before it reads another connection, so between reads a connection keeps only what a frame cut by the read boundary needs (`http2/frame_reader.zig`): the preface's progress, part of a frame header, a control frame's payload of at most 192 bytes, and where it stands in the padding and priority fields of DATA and HEADERS. DATA reaches its stream in pieces as its bytes arrive, the frame's whole length taken from the receive windows with its first piece. Only a header block is held whole, and the unfinished blocks of a lane's connections share a budget of 8 MiB: the connection whose fragment would pass it closes with GOAWAY ENHANCE_YOUR_CALM and no other connection is touched (`http2/lane_resources.zig:HeaderBlockBudget`). The TLS handshake runs in BoringSSL and hands the traffic keys to kernel TLS (`tls_handshake.zig:drive`), and the server's SETTINGS announce 64 concurrent streams, 64 KiB frames, a 512 KiB stream window and a 32 KiB header list, with a WINDOW_UPDATE that raises the connection window to 2 MiB (`writing.zig:queueServerSettingsAndAck`). One turn of a connection reads its socket at most 8 times (`http2/connection.zig:reads_per_drive_max`) and stops reading while writes are queued, so a client that does not read its responses is not read either. A connection is read only while no read poll of it is in flight, so a turn it gets for its writes or for a finished request reads nothing, and a read that leaves room in the read buffer arms the poll instead of a second read that would find the socket empty; a one-shot poll armed on a readable socket completes at once, so no byte waits for it. Each connection has one deadline at a time, from its accept on (see Deadlines).

When the server stops, the lane refuses new work and drains what it holds (`ring_driver.zig:handleStop`). Every HTTP/2 connection gets GOAWAY with NO_ERROR, a socket accepted after the stop closes before its handshake (`accept_flow.zig:acceptConnection`), and a newly matched stream gets 503. Admitted requests run to their end. The lane gives up each reader tenure over a worker it has no request on, keeps reading the workers other lanes still use until they go idle, and closes itself to posts once its command queue is empty, since a `dispatch_ready` left unrun would hold a worker slot for good. Connections still open then close as `server_stop`.

## Admission

A header block is at most 32 KiB, whether one HEADERS frame carries it or CONTINUATION frames extend it: a split block is reassembled within that and 128 frames (`connection_slot.zig:Slot.h2AppendHeaderBlock`), and a block past the bound is never decompressed and closes the connection (`reading.zig:decodeHeaderBlock`). A block within it is decompressed whole, which keeps both HPACK tables in step, within 259 fields and 32 KiB of decoded bytes (`reading.zig:decodeHeaderBlock`, `request_head.zig:max_header_count`), then checked by `request_head.zig:parse`, which also normalizes the authority once and keeps it in the head it returns (`request_head.zig:ParsedHead.authority`). A head arrives with the socket read that completed its block: each read takes one reading of the lane's clock (`runner/root.zig:LaneWorker.monotonicNowNs`), which the head keeps as `ParsedHead.received_ns`, so the lane's own decoding counts in the request's time. Since both tables are in step, a head the block decoded into but that fails the checks can still carry an answer (RFC 9113 §8.1.1): the HTTP/2 layer hands it to the lane (`admission.zig:refuseH2Stream`), which answers 431 for a head over those bounds and 400 for a malformed one, a malformed authority or a `te` field other than `trailers` (`common/http/shared.zig:headers.isConnectionSpecificField`) included, each on its own stream with an access record. A head with `expect: 100-continue` that announces a body gets its 100 before the lane's stream handler runs (`reading.zig:processRequestHead`). Every whole request head opens a stream as far as the connection's deadlines go, whatever the lane then answers on it, so it ends the pre-request deadline for good and restarts the idle one (`connection_slot.zig:Slot.noteStreamOpened`).

`admission.zig:startDynamicH2` takes the stream into the connection's table, refusing it with RST_STREAM REFUSED_STREAM past 64 streams on the connection or once the lane's 8192 stream entries are taken (`stream_table.zig:h2ReserveStream`), and classifies the stream by its path alone (`admission.zig:streamTarget`). A path under `/__collo/` belongs to the server (`server/config/pattern.zig:isReserved`): `/__collo/healthz` is answered from the server's state with atomic loads and a zero-timeout poll of the zygote's pidfd (`admission.zig:healthState`), even while the server stops, and any other such path gets 404. Every other path is matched once against the immutable route table, and a miss gets 404. A matched stream that declares a body over 4 MiB gets 413, checked only now so that its record names the route, and a matched stream gets 503 once the server is stopping. The authority selects nothing: it reaches the worker as the request's normalized authority, which also replaces its `host` header (`admission.zig:h2HeadersForIpc`).

Every answer the lane gives a stream before admitting it goes through `admission.zig:answerUnadmitted`, whose `UnadmittedAnswer` names each kind, so a new one does not build until it decides what the client gets and whether the access log hears of it:

| `UnadmittedAnswer` | The client gets | Access record |
| --- | --- | --- |
| `health` | 200 or 503 with the server's state | none: a probe every few seconds would flood the log |
| `not_found` | 404 | yes |
| `header_fields_too_large` | 431 | yes, with method and path "" when the decoder refused the block |
| `malformed` | 400 | yes, with the block's `:method` and `:path`, and no route |
| `payload_too_large` | 413 | yes, naming the route |
| `stopping` | 503 | yes, naming the route |
| `refused` | RST_STREAM REFUSED_STREAM, which the client may retry | none, since no status went out; counted as `streams_refused` |

A recorded answer takes a fresh request id, names the server as its author, no worker and `done` as its error code, starts at the head's arrival and stamps its first byte when the stream took the answer. An answer to a client still sending its request ends with RST_STREAM NO_ERROR once its END_STREAM is queued (RFC 9113 §8.1, `http2/writing.zig:answerStreamAlone`).

Admission fixes the request's one deadline, its arrival plus its definition's `timeoutMs`, and takes a request id (`service.zig:Service.allocateRequestId`, an atomic counter that skips 0), a lane request slot, a wheel entry at the deadline and the stream's binding to the request (`stream_table.zig:h2BindRequest`). A full request slab sheds that stream alone, as `refused`. The lane's slot (`request_slot.zig:RequestSlot`) holds the route key, the deadline and the access facts; the lane assigns the route, the deadline and the facts' identity, and nothing a worker sends changes them. Then the lane asks the definition's pool for a worker slot (`admission.zig:placeRequest`):

| `pool.zig:Pool.acquire` answers | The lane |
| --- | --- |
| `.acquired`: a free slot of the most recently used live worker that has one, with a reader grant | discharges the grant (`worker_registration.zig:dischargeReaderGrant`) and dispatches at once (`dispatch.zig:dispatchWithHead`) |
| `.wait`: the request is the newest waiter in the pool's FIFO | copies its head into an `OwnedHead`, since the decoded head is freed once the stream handler returns, and calls `admission.zig:growOrStrand` |
| `.full`: the FIFO holds `common/limits/pool.zig:pool_waiters_max` (256) requests | answers 503 at once (`request_finish.zig:RequestOutcome.unserved`) |

A waiter stays the lane's own state: it keeps its lane slot and its wheel entry, and the pool records only whose turn comes next. `admission.zig:growOrStrand` submits to the launcher when the pool wants its first worker, or a worker more beside live ones, which the launcher starts only on its scale-out verdict (`pool.zig:Pool.growthWanted`, [scheduler.md](scheduler.md#scale-out)). When growth is refused and the pool has no live worker and no launch in flight, it answers the waiters nothing can serve (`pool.zig:Pool.takeStranded`) with 503, its own directly and other lanes' through `dispatch_failed`.

## Dispatch to a worker

A request reaches a worker only through `dispatch.zig:dispatchWithHead`: at admission, when a `dispatch_ready` hands it a slot (`command_flow.zig:handleDispatchReady`), or when this lane frees a slot that its own waiter takes (`request_finish.zig:handOn`). A handed slot whose worker left service before the request used it goes back, with the reader grant it carried when the lane never saw the worker in service (`pool.zig:Pool.returnHandoff`), and the request asks its pool again (`command_flow.zig:handleDispatchReady`, `dispatch.zig:dispatchToWorker`). The dispatch binds the request to the worker slot, adds it to the lane's registration of the worker, keys its wheel entry to the worker at the deadline, turns the stream from `preparing` to `active`, and records the request in the worker's request table before the worker can hear of it (`request_table.zig:RequestTable.record`), so the reader's check of a descriptor it forwards for the request finds the entry (`RequestTable.forwardCheck`). The dispatch stamps its time in the request's access facts (`server/analytics/access.zig:AccessFacts.dispatched_mono_ns`), where the record's wall time starts. A request that waited for a worker launched after its admission is marked a cold start, with the worker's boot time and the time it waited in its access facts.

The `request_begin` carries the request's `DispatchWork` (`common/ipc/messages.zig:DispatchWorkView`, encoded by `common/ipc/dispatch.zig:encodeDispatchWorkInto`): the request and worker identities, the normalized authority, method, path, query, headers, body framing, route captures, the route's index in its definition's artifact (the `route` of its `RouteKey`, which a worker of the definition finds at the same index in the artifact `WorkerInit` carried), the deadline, an egress token, and the pool slot the request holds (`worker_slot`), at whose index the worker writes the request's live slot. A worker refuses a begin whose pool slot an unfinished request still holds (`error.WorkerSlotInUse`), or whose id it holds (`error.RequestIdInUse`), as a protocol error that ends its loop, before it writes the live slot (`worker/request/ingress/runtime.zig:requireUnheld`). A request stays unfinished from its begin to the finish that sends its `request_done`, so a server that gives a pool slot back only at that packet never meets the refusal, and every request a worker holds has a pool slot of its own. The lane mints the token from its own lease on the current gateway (`server/gateway/lease.zig:Lease.mint`) for the worker's session, which it reads under the pool's mutex because the launcher rewrites it on a reattach (`supervisor.zig:Supervisor.workerEgress`). The token holds the request's identity and deadline and the network policy of the request's route (`dispatch.zig:requestTokenFields`, `server/routes/network.zig`), in 56 bytes with a 16-byte HMAC-SHA256 tag under the gateway's key (`common/ipc/egress_token.zig`). A lease that holds another gateway's key mints `egress_token.none`, and the worker refuses that request's fetches itself. The dispatch takes no manager lock and makes no gateway call.

The lane encodes the `DispatchWork` into its own 1 MiB scratch and sends descriptor and payload as one SEQPACKET datagram through the worker's `dispatch_send_scratch`, under `Record.send_mutex`, since every lane that holds a slot of the worker may send to it (`dispatch.zig:sendBegin`, `worker_table.zig:Record.send_mutex`). Once the begin is in the socket, the wheel entry moves to the deadline plus `hard_timeout_grace_ns` (`dispatch.zig:beginReachedWorker`), and the body the stream buffered while it waited follows. A send that would block is backpressure: the begin is parked with its own copy of the payload, zeroed when freed because it holds the token (`request_slot.zig:ParkedBegin`), a writability poll on the worker's control socket retries it (`ring_driver.zig:armWorkerControlWritable`), and the request's deadline still bounds the wait. A request's sends leave in order: its begin, then a reset, then its response credit, then the buffered body (`dispatch.zig:flushRequestSends`). A send that fails for the worker's doing stops the request's sends and queues the worker's death path for the end of the running handler (`dispatch.zig:failSend`).

## Bodies and credit

A request body is bounded by its `content-length`, or by 4 MiB without one (`stream_table.zig:h2RecordRequestBodyChunk`, `common/limits/http_body.zig:MATERIALIZED_BODY_BYTES_MAX`). A body that breaks its length gets 400 and one over the bound gets 413 (`request_body.zig:rejectH2RequestBody`): a waiting request ends with the answer, and a dispatched one leaves its stream and is cancelled toward its worker. Either way the request's access record reports the lane's answer, from the server, with error code `bad_request`; for a dispatched request the slot keeps the answer (`request_slot.zig:RequestSlot.local_answer`) over whatever the worker's `request_done` says, since the client never got the worker's response.

The HTTP/2 credit of body bytes goes back to the client only once the server no longer holds them (`http2/connection.zig:DataFrameHandling`). A stream whose request waits buffers its DATA with the credit withheld (`flow_control.zig:h2AppendPreparingBody`); the buffer leaves after the begin, and its credit is owed once the worker has the bytes (`request_body.zig:flushPendingBody`). Owed credit goes out in WINDOW_UPDATE frames at the tail of the next write that goes through the connection's write queue, which every response head and control frame does (`writing.zig:flushPendingWrite`; DATA written straight from a buffer carries none), or in a write of its own once the client's view of the connection's window, or of an open stream's, is at or below half of what the lane advertised: a drive checks as it starts and after each socket read, and credit owed outside a drive is checked where it is owed or by the turn its connection gets (`writing.zig:queueDueWindowUpdates`, `flow_control.zig:h2WindowUpdateDue`, which proves that waiting for a write never keeps the client's window that low past the read that brought it there, and that a sender stalls only when the server holds a whole window); a stream whose END_STREAM arrived can take no more DATA and is owed nothing of its own. A dispatched stream sends each chunk at once, inline up to `shared_payload_threshold` (32 KiB) and through the worker's server-to-worker payload ring above it, under `send_mutex` because the ring takes one producer at a time (`request_body.zig:sendBodyChunk`); a run of up to 32 unpadded DATA frames goes as one batch packet (`reading.zig:tryHandleDataFrameBatch`, `request_body.zig:sendBodyBatch`). A chunk that finds the socket or the ring full queues on its stream behind the request's earlier bytes with its credit held, so a worker that stops reading stalls the client's sender. The receive windows bound what a stream can buffer: 512 KiB per stream and 2 MiB per connection, below the buffer bounds that `flow_control.zig` asserts at compile time.

A ring has one writer side and one reader side, and a writer that finds no room marks the ring's header and checks the room once more; the reader's next release clears the mark and signals the writer's credit eventfd, and a release that finds no mark makes no system call (`common/ipc/ingress_channel/payload_ring.zig:SharedPayloadReadRelease`). A lane whose body finds the server-to-worker ring full first registers itself for the worker slot its request holds (`worker_table.zig:Record.body_waiters`), then marks the ring (`request_body.zig:waitForRingRoom`). The worker's release signals its own completion eventfd, which only the worker's reader lane polls and which carries nothing else; after draining it with one read (`event_sources.zig:drainEventFd`) the reader raises the `payload_credit` wake bit on each registered lane (`request_body.zig:handleWorkerRingCredit`), whose next pass retries every send blocked on a ring (`dispatch.zig:retryRingBlockedSends`). No lane polls a credit eventfd. The worker-to-server ring works the same way in the other direction: the worker marks it when a response chunk finds no room, and the reader's release signals the worker's payload credit eventfd (`worker/serve/response_payload_writer.zig`).

Each request may hold `common/limits/http_body.zig:INGRESS_RESPONSE_CHUNKS_IN_FLIGHT_MAX` (4) response body chunks of at most `INGRESS_RESPONSE_CHUNK_BYTES` (64 KiB) that its client has not taken yet, and both ends start from that window at `request_begin`; `common/ipc/response_credit.zig:Window` says what holds credit and for how long. The lane that owns the request counts the chunks it holds (`request_slot.zig:RequestSlot.response_credit`), with the same `Window` the worker counts by, and a fifth is the worker fault `response_descriptor_invalid`. A chunk keeps its bytes in one allocation from the moment the lane takes them until the client socket has accepted all of them, and queued DATA frames point into it (`write_queue.zig:ResponseChunk`). Once its last byte is written, the lane frees it and counts it retired (`dispatch.zig:responseChunkRetired`); once every chunk one write retired is counted, it sends each owner's worker a `response_credit` with the cumulative total, retired chunks plus the window, but only when that total raises the one the worker holds and the worker's credit by the lane's count, that total less the chunks the lane accepted, is at most half the window (`dispatch.zig:grantResponseCredit`, with the proof at `request_slot.zig:RequestSlot.response_credit_sent`). A response of fewer than half the window's chunks therefore gets no grant, a long one gets one per half window or more, and a worker never waits at zero credit for a grant that is not on its way. The chunk names its request by key, so a write that completes after the request ended gives a later request in the slot nothing. A full control socket keeps only the newest total for the writable poll, and a reset or ended response sends none. Ring credit and response credit are separate: the lane copies ring bytes into the chunk and releases the ring at once.

A client's RST_STREAM ends a waiting request (`stream_gone`, recorded as 499) and a dispatched one whose begin never left. A request whose begin reached the worker stays until the worker's `request_done` ends it, after a `request_reset` tells the worker the stream is gone, so a reset never frees a slot the worker may still use (`request_body.zig:handleH2ResetFrame`, `dispatch.zig:cancelRequestToWorker`).

## The reader lane and forwarding

One lane at a time reads a worker's output: its control socket, completion eventfd and pidfd (`worker_registration.zig:armWorkerPolls`). The reader is the first lane to take a slot of a worker that has none, and it keeps the role while the worker alternates between idle and busy; [scheduler.md](scheduler.md) covers how the role moves. Every lane with a slot sends to the worker, and the reader forwards what belongs to other lanes through their command queues.

Besides its descriptors, a worker sends on its control socket, once at most, the notice that it asks to be retired (`common/ipc/worker_retiring.zig`, `common/ipc/messages.zig:WorkerRetiringReason`), when its routes all failed, a termination poisoned its VM, or it detached from its egress session on its own for a gateway defect (`egress_detached`, [egress.md](egress.md#sessions)). The reader takes the worker out of service with no death (`pool.zig:Pool.retireOnNotice`): its slots go to no new request, the requests it holds finish on it, since it keeps answering them, and its definition's waiters get a replacement launch or 503 (`worker_control.zig:retireOnNotice`). Once no lane holds a slot of it, its reader gives the role up through its own queue (`release_worker`), and the reaper retires it as `recycled`. The notice of an idle worker no lane reads reaches the pool through the reaper's watch instead ([scheduler.md](scheduler.md#the-reaper)). A notice of another size or with an unknown reason is the fault `retiring_notice_invalid`.

The reader drains up to 64 packets per wake (`worker_control.zig:control_packets_per_drain_max`) and stops early at a connection with bytes to write, so they go out before more of the response (`worker_control.zig:Pace`), and after a packet that leaves the worker with no request whose `request_done` is still to come (`request_table.zig:RequestTable.awaitingDoneCount`), instead of a receive that would find the socket empty; the control poll it arms again completes at once for a packet sent since. It receives a packet only while the worker's forwarding window still holds a whole batch of 32 descriptors: at most 64 of a worker's forwarded response descriptors and answers to their ring payloads wait in lanes' queues at once (`common/limits/ingress.zig:forwarded_commands_per_worker_max`, `h2_worker_ipc.zig:windowHasRoom`), so a worker that writes faster than the lanes it answers can apply waits in its own socket. A full window stops the reader's control poll, not its completion eventfd's, and the release that makes room for a batch again raises the `window_reopened` wake bit on the reader, which resumes the drain (`h2_worker_ipc.zig:releaseForwardUnit`, `worker_control.zig:resumeWindowBlockedReaders`). The reader takes a unit only while the window has one (`h2_worker_ipc.zig:acquireForwardUnit`), so the count never passes the window, every decrement is a release, and no step back into room goes unannounced. A drain that must read through, the grace backstop's or a dead worker's last read, ignores the window, and a response descriptor that then finds it full drops as a refused post does; a `request_done` takes no unit, so a full window never loses one. A packet that carries descriptors, is shorter than its kind or is of a kind the channel does not carry is a worker fault, and the rest decode with the reader's account of the worker-to-server ring (`completions.zig:Registration.ring_payloads`). A descriptor acts only on the request it names exactly: one whose request ended or whose stream went away is a race and drops, and any other mismatch is the fault `descriptor_names_no_request` (`h2_worker_ipc.zig:resolveDescriptor`). A response head is decoded within 256 headers and 16 KiB (`writing.zig:max_worker_response_header_count`, `max_worker_response_header_bytes`) and encoded with the connection's HPACK encoder. The lane decides whether a head went out from its own HTTP/2 record (`stream_table.zig:responseHeadQueued`); no flag a worker writes enters that decision.

A response descriptor of another lane's request travels as `forwarded_descriptor` (`h2_worker_ipc.zig:forwardDescriptor`), once the reader checked it against the worker's request table: a request the worker holds under another key is the fault `descriptor_names_no_request`, and one the worker does not hold drops at the reader (`request_table.zig:RequestTable.forwardCheck`), so a worker's output reaches another lane's queue only for that lane's own requests on that worker. An inline payload's decoded copy moves into the command, and from there into the owner's chunk; a ring payload stays in the ring, held in the reader's account until the owner answers `payload_consumed`. The owner answers every ring payload it was forwarded before it drives the connection or finishes the request, and the reader frees ring bytes only over the answered prefix, in ring order (`h2_worker_ipc.zig:handlePayloadConsumed`). When the owner's queue refuses a descriptor, the reader drops the rest of that response (`completions.zig:ForwardLoss`) but still forwards the request's `request_done`, so no client gets a response with a gap: a lost head ends the request with 502 when the `request_done` arrives, and after a lost later descriptor the `request_done` ends the request at once and resets its stream (`request_finish.zig:finishDispatched`).

A worker ends each request with `request_done`, the last descriptor it sends for it ([Completion and finish](#completion-and-finish) gives its contract), so everything the worker sent for the request is ahead of it in the socket, and in the owner's queue when the reader forwards both. The reader decodes it once into a `RequestDone` (`request_done.zig:decodeDone`), and the lane that owns the request acts on that record only for the request it names exactly: a live request of the lane at its key, dispatched to that worker under the same request id and stream, whose begin reached the worker (`request_done.zig:completeRequest`). One whose request ended, or whose slot holds a later request, drops as stale, counted (`stale_request_done`); any other mismatch is `descriptor_names_no_request`. One for another lane's request travels decoded as a `forwarded_request_done` (`lane_commands.zig:ForwardedRequestDone`), outside the forwarding window: a request keeps its pool slot until its owner applies it, so the reserve holds one per request in flight. The worker's request table lets the reader forward one per request and nothing of the request after it, and marks it forwarded only once the post went in (`RequestTable.forwardCheck`, `markDoneForwarded`); a refused post, which only a stopped owner lane or a queue full past its reserve can make, is logged and leaves the request to its grace backstop.

| Command (`commands.zig:Command`) | Sent by | The receiving lane | When the post is refused |
| --- | --- | --- | --- |
| `dispatch_ready` | the lane whose `Pool.release` handed a slot on, or the launcher's publish (`service_deps.zig:postHandoff`) | discharges the reader grant, then dispatches the waiting request or gives the slot back (`command_flow.zig:handleDispatchReady`); a slot of a worker that left service meanwhile goes back with its grant (`pool.zig:Pool.returnHandoff`) | the sender returns the slot with its grant (`pool.zig:Pool.returnHandoff`), which may hand it to the next waiter |
| `dispatch_failed` | a lane, the launcher or the metrics thread after `Pool.takeStranded` | answers 503 if the request still waits | the request gets 503 at its deadline |
| `forwarded_descriptor` | the worker's reader | applies the response descriptor as its own read and answers its ring payload (`h2_worker_ipc.zig:handleForwardedDescriptor`) | the reader frees the ring bytes and drops the rest of the response; it takes only reserved places, so it is refused when the lane is not running or when obligations past their share fill the reserve |
| `forwarded_request_done` | the worker's reader | finishes the request as its own `request_done` (`command_flow.zig:applyForwardedRequestDone`) | the request waits for its grace backstop, which faults the worker; the reader logs the loss |
| `payload_consumed` | the request's owner | frees the answered prefix of the ring | the bytes stay held, and the payloads behind them wait until their requests' deadlines |
| `release_worker` | a lane granted `transfer_from`, the reaper retiring an idle worker, or the lane that freed the last slot of a worker retiring on its notice, its reader included | gives its tenure up if the pool lets it go (`command_flow.zig:giveUpTenure`) | the pool forgets the request (`Pool.releaseRequestLost`), and the reaper posts again on its next pass |
| `worker_died` | the lane, reaper, metrics thread or launcher that saw the death | runs the death path for its own requests and tenure (`worker_fault.zig:faultWorker`) | the lane learns of the death from the worker's channels or its requests' deadlines |

A lane's queue has 1024 ordinary places and a reserve: for each entry of each pool's table, one death, one reader grant, one place per slot of its definition's `concurrency` for a forwarded `request_done`, and the entry's 64 places of forwarded response output (`lane.zig:obligationReserve`, `runner/root.zig:servedDefinitions`). A forwarded response descriptor and its payload answer take only reserved places, so a worker's response output never takes an ordinary place. A death, a reader grant and a forwarded `request_done` take a reserved place first and an ordinary one once the reserve is full. Every other command takes only ordinary places (`commands.zig:Command.placement`, `Queue.push`). Commands to one lane run in the order they were posted, and each handler checks the keys its command carries against the lane's own state before it acts (`command_flow.zig`).

## Completion and finish

A worker reports each request's end as `request_done`, the last descriptor it sends for that request: 64 bytes inline (`common/ipc/ingress_channel/framing.zig:RequestDonePayload`), holding the done status (`RequestDoneStatus`), the HTTP status of the head it sent or 0, and what the request measured, `exec_ns`, `waiting_ns`, `io_ns`, `cpu_ns`, `client_served_bytes`, `fetch_sent_bytes` and `fetch_received_bytes`; the two fetch counts are the request's fetch body bytes as each packet crossed, with no framing, header or TLS byte ([egress.md](egress.md#a-fetch-end-to-end)). The worker builds a `RequestDone`, whose status is the enum, and `sendRequestDone` encodes it (`encodeRequestDone`); the receiving side gets a `RequestDone` only from `decodeRequestDone`. It rides a single packet or a batch entry, in socket order behind the request's response descriptors. Both decoders refuse one whose flags are anything but `inline_bytes`, whose payload is another length or whose `aux` is nonzero (`framing.zig:validateDescriptor`), and one whose reserved bytes are nonzero, whose status the enum does not name or whose HTTP status is neither 0 nor in 100 through 599 (`framing.zig:decodeRequestDone`); the refusal is the packet's, `ingress_channel_undecodable`. A worker refuses the operation like any other the server never sends it. It sends a request's `request_done` as the last entry of the packet that carries the response's last descriptor, the head or chunk that ends the stream, the stream's end or its reset, or alone when the response has no such step left (`worker/serve/response_finish.zig:finishRequest`). The lane applies that packet's descriptors in order, so the response's end goes to the client's queue and the `request_done` gives the slot back in the same pass, before the client can have read the response and sent its next request, which would otherwise wait for a slot the worker no longer uses. A `request_done` alone that finds the control socket full waits in the worker's outbox (`worker/runtime/requests.zig:Requests.done_outbox`), which holds at most one packet per pool slot, since the lane gives a pool slot back only at its request's `request_done` or the worker's death (`request_done_outbox_capacity`); a packet past it stops the worker. A last packet that carries a step of the response waits with that step in the request's response outbox instead ([request-timeline.md](request-timeline.md#where-the-numbers-land)). The finish leaves the request's live slot as it is, so the slot keeps the request and its final CPU until the next begin on its pool slot (`common/worker_state/page/live_slots.zig`).

A `request_done` finishes its request at once with the worker's measures, whatever the stream holds: a response whose end the lane queued drains to the client, and one whose end never came is reset, since nothing of the worker follows it (`request_finish.zig:leaveStream`). One that leaves the client without a response head on an open stream gets the lane's 502 (`request_finish.zig:requestDoneLeftNoAnswer`). The access record carries the status of the response head the lane queued for the worker, the status the client received (`server/analytics/access.zig:AccessFacts.response_status`); the `request_done`'s HTTP status counts only when no head went out, and 0 then records 499 for `client_closed` and 502 otherwise (`request_finish.zig:workerDoneStatus`, `doneHttpStatus`). A `request_done` for a request whose begin never left is the fault `descriptor_names_no_request`, since an honest worker cannot name such a request (`request_done.zig:resolve`).

A request whose begin reached the worker finishes only at its `request_done`, its worker's death or the lane's teardown, so its pool slot comes back only once the worker holds it no more, and `concurrency` bounds the requests in flight in the worker process. The client does not wait for that: a client's reset ends its stream and a body the lane refuses gets its answer at once, while the request waits for its `request_done` after a `request_reset` (`request_finish.zig`, `dispatch.zig:cancelRequestToWorker`); at the deadline the worker answers 504 itself, and the grace backstop enforces it with the worker's death ([Deadlines](#deadlines)).

Every request ends in `request_finish.zig:finishRequest`, once, whatever ended it. A dispatched request emits its access record with its usage, leaves its worker's request table (`RequestTable.end`, or `remove` when its begin never reached the worker), answers or resets its stream, leaves the worker's registration, frees its lane slot and wheel entry, and only then gives its worker slot back (`request_finish.zig:finishDispatched`). A waiting request leaves the pool's FIFO (`pool.zig:Pool.cancelWaiter`); if a handoff took it first, its `dispatch_ready` finds the request gone and gives the slot back.

| `request_finish.zig:RequestOutcome` | The client gets | Access status | Usage |
| --- | --- | --- | --- |
| `worker_done` | the worker's response, or 502 when the worker ended with no head on an open stream | the status of the head the lane queued, else the worker's, or the lane's 502 | the `request_done`'s measures, origin `worker` |
| `waiter_expired`, `unserved` | 503 | 503 | none |
| `rejected` | the lane's own answer to a waiting request | that answer's status, error code `bad_request` | none |
| `stream_gone` | nothing, the stream is gone | 499 | none for a waiting request; no measures, origin `server`, for a dispatched one |
| `send_expired` | 504; the worker stays in service | 504 | no measures, origin `server` |
| `deadline_expired` | 504, or RST_STREAM after the head | 504, its `worker_fault` naming the deadline fault, `deadline_grace_expired` or `owner_overran` | the server's floor |
| `worker_died` | 502, or RST_STREAM after the head | 502, its `worker_fault` naming the fault reason | the server's floor, with no CPU when the error code is `internal_error` |
| `shutdown` | nothing; the connection closes | 503, error code `internal_error` | a floor with no CPU for a dispatched request |

A dispatched request whose begin never reached the worker carries origin `server` and no measure, whatever ended it. The lane writes the access record's identity, duration, every status it synthesizes and the status of the worker's response head it queued; a worker's `request_done` supplies its error code and its measures, and its status only when no head of the worker went out (`request_finish.zig:emitAccessRecord`), and neither status nor error code once the lane answered the client itself. A dispatched request's record also carries what it used (`server/analytics/access.zig:Usage`): `origin`, the server's `wall_ns` from the dispatch (`AccessFacts.dispatched_mono_ns`) to the lane's end, and the worker's `exec_ns`, `waiting_ns`, `io_ns`, `cpu_ns`, `client_served_bytes`, `fetch_sent_bytes` and `fetch_received_bytes`; a request no worker was dispatched has none of these fields. A worker can end its own request with `internal_error`, the code the server uses for its own failures, and `origin` tells the two apart. The record goes onto the lane's access ring of 2048 records, with one producer and one consumer, which the metrics thread drains every 100 ms into `access.jsonl`; a full ring, or an access stream the sink has no room for, drops the record with its usage and counts it (`server/analytics/access.zig:AccessRing`, `analytics_drain.zig`, `server/analytics/sink.zig:Sink.appendLossy`). Before admission, every answer with a status but the health answer writes a record (see Admission).

The request table entry the lane records at dispatch (`server/supervisor/request_table.zig:RequestTable.record`) lives exactly as long as the request: the finish frees it before the worker slot goes back, with `end` for a request whose begin reached the worker, which leaves its route among the table's last 256 ended requests for the console drain, and with `remove` for one whose begin never left, which leaves nothing, since a worker that never got the begin has no request to name. While the entry lives, the worker's reader forwards a descriptor of another lane's request only under the key the dispatch recorded, and the request's `request_done` once (`RequestTable.forwardCheck`, `markDoneForwarded`); whatever the worker sends for the request after that drops as stale. A request the server ended without the worker's `request_done` gets the server's floor, read off the worker's page while the lane still holds the request's worker slot (`server/supervisor/worker_table.zig:Record.usageFloor`): the CPU of the live slot at that slot's index while it holds the request's id and generation, or the larger of that and the running window's CPU when the sentinel last saw the request running, none when the request ended `internal_error`, and no other measure. A `request_done` read after the lane ended its request finds neither the request slot nor the entry, so no request gets two records.

The freed slot goes to the oldest waiter at once (`pool.zig:Pool.release`). A waiter of this lane is dispatched on it before the finish returns, another lane's waiter gets `dispatch_ready`, a refused post returns the slot to the pool, which may hand it on again, and a dead worker's last slot sends the worker to the reaper (`request_finish.zig:handOn`); no retry timer exists on the path. The finish tells the gateway nothing: the gateway keeps nothing per token, and the worker stops the request's fetches at its own cleanup ([egress.md](egress.md#the-token)).

## Failure domains

A failure belongs to a connection, a worker, the lane or the server (`fault.zig`). A loop handler returns `LaneFault!void`, so the lane's own faults are the only errors that leave one; a client's or a worker's failure is a value the handler acts on before it returns: `ConnectionOutcome` (`keep`, or `close` with a `ConnectionCloseReason` and a GOAWAY code), `WorkerOutcome` (`ok`, `would_block`, or `fault` with a `WorkerFaultReason`) and, for a worker's response, `ResponseQueueOutcome`. Each callee's errors are sorted by its own table where it is called (`fault.zig:classifyConnectionError`, `classifyWorkerError`, `classifyResponseQueueError`), and a table names every error of its callee, so an error a callee adds does not build until someone assigns its domain.

A connection closes on a TLS failure, an HTTP/2 connection error (a protocol, frame size or flow-control error, an HPACK desync, a SETTINGS frame of more than 32 entries, a header block of more than 128 frames, more than 128 control or empty DATA frames in one read, where a WINDOW_UPDATE counts only past the two that each DATA frame the server sent earns (`flow_control.zig:h2SpendEarnedWindowUpdate`), since a client may return every frame's credit to the connection and to the stream), a header block past 32 KiB in any number of frames, a header block the lane's budget cannot hold, a write queue past 1 MiB, a failed allocation sized by the client, the peer's close, its pre-request, idle or stall deadline, or the server's stop (`fault.zig:ConnectionCloseReason`). The close takes two steps. The decision stops the connection's reads and puts GOAWAY at the end of its queue when HTTP/2 can still speak, and the connection's next turn resets each of its streams toward its worker through the client-reset path, flushes the GOAWAY and tears the connection down (`connection_flow.zig:closeRuntimeConnection`, `finishClose`). A failure of one stream answers or resets that stream alone: a head over its bounds or malformed (`admission.zig:refuseH2Stream`), a body over its bounds (`request_body.zig:rejectH2RequestBody`), or a response the stream cannot buffer, which also cancels the request toward a worker that stays alive (`h2_worker_ipc.zig:actOnQueueError`).

A worker fault runs the death path (`worker_fault.zig:faultWorker`). The pool takes the worker out of service first (`pool.zig:Pool.markDead`); a reader whose fault reason leaves the output trusted (`peer_closed`, `exited`, `deadline_grace_expired`, `owner_overran`, `egress_session_failed`, `egress_session_removed`, the last because a worker whose gateway removed its session broke only the egress protocol) reads and forwards the last of it (`worker_fault.zig:finalDrainTrusted`), so a `request_done` in it ends its request as the worker reported it; the other lanes the death names get `worker_died`; and the lane ends its own requests on the worker with 502, or with 504 for each one past its own deadline when the worker died of a deadline (`deadline_grace_expired` or `owner_overran`), or with RST_STREAM after a head, putting the reason into each access record. A fault met inside a stream handler takes the worker out of service at once and leaves the rest for the end of the handler (`worker_fault.zig:deferWorkerFault`). The lane then asks for a replacement or strands the waiters (`admission.zig:growOrStrand`), and the reaper does the retirement (`service_deps.zig:queueRetirement`); no kill, exit wait or cgroup removal runs on a lane.

| `fault.zig:WorkerFaultReason` | Cause | Error code (`worker_fault.zig:errorCodeForFault`) |
| --- | --- | --- |
| `packet_short`, `packet_too_large`, `unknown_kind` | a control packet shorter than its kind, larger than 1 MiB, or of a kind its channel does not carry | `crash` |
| `unexpected_descriptor`, `too_many_descriptors`, `zero_length_datagram_with_descriptors` | a packet that carries descriptors, more than one receive holds, or an empty datagram with descriptors | `crash` |
| `ingress_channel_undecodable` | a packet that fails to decode, a malformed `request_done` among them | `crash` |
| `descriptor_names_no_request`, `response_head_invalid`, `response_descriptor_invalid` | a descriptor for a request the worker was not sent, a `request_done` among them, a head over the caps or with a header the client may not receive, a descriptor its stream's response state does not admit | `crash` |
| `payload_ring_invalid` | ring cursors that contradict each other, or a descriptor claiming bytes the ring does not hold | `crash` |
| `channel_failed` | a socket or eventfd of the worker that failed with no other reason | `crash` |
| `peer_closed`, `exited` | a hang-up of the control socket, the exit its pidfd reports | `memory` when the page or the cgroup says so (`worker_table.zig:Record.classifyDeath`, `worker_table.zig:Death.errorCode`), `crash` otherwise |
| `deadline_grace_expired` | a request past its deadline and the grace | `deadline` |
| `owner_overran` | the VM thread still working for an owner past that owner's deadline by the grace plus one metrics interval, which the metrics thread reads off the page (`analytics_drain.zig`) | `deadline` |
| `log_ring_corrupt` | a console ring on its page that contradicts itself, seen by the metrics thread | `crash` |
| `retiring_notice_invalid` | a `worker_retiring` notice of another size or with an unknown reason | `crash` |
| `egress_session_removed` | a session its gateway removed for a protocol violation, for which the launcher retired the worker (`Launcher.egressSessionLost`) | `memory` when the page or the cgroup says so, `crash` otherwise (`worker_fault.zig:deathStatus`) |
| `allocation_failed` | an allocation for a packet that failed | `internal_error` |
| `egress_session_failed` | no gateway able to give the worker a session after its gateway was lost | `memory` when the page or the cgroup says so, `internal_error` otherwise |

A lane fault is a broken invariant of the lane's own state: a ring error that is not transient, or a transient one 64 times in a row (`fault.zig:ringErrorIsTransient`), a completion tag it never packed, an accept tag naming another lane, a fatal accept errno, a failure of its timerfd or command eventfd, a table or queue sized from its own limits that overfills, records of its own that disagree, a message it built wrong, or the creation of any of these at start (`fault.zig:LaneFault`). The lane thread stores the error, marks itself failed and raises the stop flag (`runner/root.zig:LaneWorker.threadMain`). The service's thread sees it within 5 ms, stops the lanes, then the metrics and console threads, which drain what the lanes produced until the lanes have joined (`Service.observability_stop`), then the launcher and the reaper, and returns the error, so the server exits (`service.zig:Service.run`, `stopAndDrainForExit`); a lane owns one share of every connection on the node, which is why its fault stops the server. Teardown after a lane fault ends each request as `shutdown`, closes each connection and announces the deaths the lane still owed (`ring_driver.zig:deinitRuntime`). The server's own faults are the zygote's exit, a listener failing and a boot that does not complete (`fault.zig`), and off the lanes a post or pool call that fails stops the server too (`service.zig:Service.recordFatalError`).

## Deadlines

A request has one deadline, fixed at admission from its definition's `timeoutMs` and counted from the read that brought its head (`ParsedHead.received_ns`): 30 s by default (`server/config/model.zig:default_settings`) and at most 15 min (`common/limits/server.zig:request_timeout_ms_max`). It travels in the `DispatchWork` and in the egress token, and the lane's wheel entry follows the request:

| The request | Its wheel entry | When the entry fires |
| --- | --- | --- |
| waits for a worker slot | at the deadline | 503 (`waiter_expired`), and the waiter leaves the FIFO |
| holds a slot, its begin parked on a full socket | at the deadline | 504 (`send_expired`); the worker never heard of the request and stays in service |
| its begin reached the worker | at the deadline plus `hard_timeout_grace_ns`, 250 ms (`supervisor.zig:default_hard_timeout_grace_ns`) | the grace backstop |

A worker answers 504 itself when the deadline passes, so the backstop fires only for one that did not (`deadline_driver.zig:expireDispatchedRequest`). A worker whose VM thread hangs for an owner no lane watches, its worker owner or an evaluation after `WorkerReady`, has no request backstop: the metrics thread finds it on its page, past the owner's deadline by the grace plus one metrics interval, and faults it as `owner_overran` (`analytics_drain.zig`), which ends its requests as the grace backstop does. The grace backstop first lets a `request_done` that came in time win: a lane that reads the worker reads its control socket for up to 64 drains, through any connection's backlog and the forwarding window (`worker_fault.zig:drainControlToEnd`), and a lane that only holds the request runs the commands the reader forwarded to it (`deadline_driver.zig:expireDispatchedRequest`). A `request_done` found there ends the request, counted as `request_done_at_backstop`. Otherwise, a worker that kept its socket filling through the whole read included, the worker takes the fault `deadline_grace_expired`, which answers every request on the worker past its own deadline 504, on every lane, and the others 502, or RST_STREAM after a head (`worker_fault.zig:finishRequestsOnWorker`). A healthy worker therefore never dies of the deadline of a request its reader lane holds; a lane that does not read the worker sees only what the reader forwarded so far ([Open points](#open-points)).

The deadline wheel, the heap of connection deadlines and the accept backoff share the lane's one timerfd (`deadline_driver.zig:nextDeadlineNs`). An entry due before every other re-arms it (`admission.zig:insertWheelEntry`), a removed entry may leave it armed early, which costs one spurious wake, and one wake expires at most 64 entries (`deadline_driver.zig:expired_batch_max`). The pool drops a waiter whose deadline passed when a slot frees, since its lane answers it (`pool.zig:Pool.release`). The access record's duration starts at the head's arrival too, so the lane's decoding and the time spent waiting show in it.

A connection has one deadline at a time, one entry in the heap, and its state chooses which (`deadline_driver.zig:desiredDeadline`):

| Deadline | Runs | At expiry |
| --- | --- | --- |
| pre-request, 3 s | from the accept until the client's first whole request head, whatever else it sends | GOAWAY NO_ERROR, then the close |
| none | while a stream serves a request, waiting for a worker or dispatched (`connection_slot.zig:Slot.servesRequest`), and no header block is open | |
| stall, 10 s | from the last byte read or written, while a header block is open, or while no stream serves a request and the lane holds something only the client can move: part of a frame, writes the socket has not taken, or response bytes the send windows hold back | the close at once, without waiting for the write queue |
| idle, 300 s | from the moment the connection last came to serve no request, while nothing stalls; every new stream restarts it, one the lane answers alone included, and no other frame does | GOAWAY NO_ERROR naming the last stream, then the close once that is written |

While a stream serves a request, that request's deadline bounds whatever the connection holds for it, so a client that stops reading a long response, or in the middle of a request's DATA frame, loses its connection only when the request ends, and the connection's other streams with it. An open header block is the exception: it stops every other frame of the connection and its CONTINUATION frames must follow without a gap (RFC 9113 §6.10), so it stays under the stall deadline. Every request's finish, whatever ended it and wherever it ran, queues its connection for a turn (`request_finish.zig:finishRequest`), whose drive files the deadline the connection then calls for. A close that flushes its GOAWAY is bounded by the stall deadline, counted from the later of the last byte and the close's decision, so a client that stopped reading before an idle or pre-request expiry still gets a whole stall period to take the GOAWAY. The heap is re-keyed lazily: a deadline that moves later, as the stall deadline does with every byte, only changes the state it follows from, and its old entry, when it expires, files the later one; only a deadline that appears or moves earlier touches the heap at once, at the end of every drive, the loop's turn of a connection and the reader's drive of one with bytes waiting alike (`deadline_driver.zig:syncConnectionDeadline`, `connection_flow.zig:driveHttp2`).

## Open points

A lane that holds a request but does not read its worker runs only the commands already forwarded to it when the grace backstop fires (`deadline_driver.zig:expireDispatchedRequest`), so a `request_done` the worker sent in time and its reader has not read yet, because the reader is busy or its window is full, loses to the fault, and every request in flight on the worker ends with it.
