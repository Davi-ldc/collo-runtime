# Security

This reference describes the trust boundary around a worker as the code keeps it: which files the server reads for a definition, the confinement a worker is born into, what it holds afterwards, every place it writes state another process reads and how that reader reads it, what a worker fault costs, what the egress gateway trusts, the gates in `runtime/tests/conventions.zig` that hold the reading rules in place, and what a compromised worker can still reach. The mechanics belong to the code and its `//!` headers: `zygote/child_boot.zig` and `zygote/worker_boot/` for the confinement, `common/worker_state/page/`, `common/ipc/ingress_channel/` and `common/ipc/egress_shared/` for the shared memory, `server/ingress/fault.zig` and `server/ingress/runner/` for the server's reading, and `egress/gateway/runtime/` for the gateway's; [egress.md](egress.md) covers the egress session and its token. Paths are relative to `runtime/src/`, a reference reads `file.zig:symbol`, and the code wins wherever this page disagrees with it.

## The boundary

A worker runs one tenant's code and is untrusted from its first instruction. The process is the hard boundary: a worker runs the routes of one worker definition, every one of them (`server/supervisor/launcher.zig:receiveForkReply` hands it the definition's whole artifact), and the workers of one definition share a security cell at the gateway (`server/gateway/manager.zig:securityCellIdForDefinition`). Realms inside a worker separate the routes' state, not their trust: code that escapes the engine reaches everything in its process, the bindings of every route of its definition, the tokens of its requests in flight, its sockets and its mappings among them, so every layer outside the process is built to hold against a worker that runs native code: the kernel confines the process, and the server and the gateway take every byte it writes as hostile input.

## What the server reads for a definition

The server reads a definition's modules once, at boot, and only from the definition's root: the deepest directory holding the entries of its routes, which no import widens (`server/routes/artifacts.zig:definitionRoot`). A static import whose path leaves the root fails the boot with file and line, and a string-literal `import()` that does is left out without a look at the file. Every module is opened beneath an `O_PATH` descriptor of the root with `openat2` and `RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS`, non-blocking, and read only when `fstat` finds a regular file (`server/routes/module_graph.zig:Root.openModule`, through `common/os.zig:fd.openat2`), so a `..` or a symlink, relative or absolute, never leads the server to open a file outside the root, and a FIFO cannot hold its boot. One definition's code therefore never makes the server pack another definition's files. The root's own path is the operator's, and symlinks in it are followed; a root that holds another tenant's files, such as an entry at `/srv/index.js` above `/srv/b/`, gives that definition's code those files, so the operator must not lay definitions out that way.

## Birth and confinement

The launcher creates the worker's cgroup leaf with its limits before the fork. The zygote's fork loop checks that the leaf is an empty cgroup2 directory (`zygote/worker_boot/cgroup.zig:validateEmptyWorkerCgroupDirFd`) and clones the child into it with `clone3(CLONE_INTO_CGROUP | CLONE_PIDFD | CLONE_CHILD_SETTID | CLONE_CHILD_CLEARTID)` (`zygote/fork_loop.zig:serveForkRequests`, `common/os.zig:cloneForkWithPidFd`), so the limits hold before the child's first instruction and the child's glibc knows its own thread id, which the child checks first (`zygote/child_boot.zig:validateOwnThreadIdentity`). The zygote is single-threaded at every clone, sets the child's `OOM_SCORE_ADJ_WORKER` and lets the kernel reap it (`fork_loop.zig:installWorkerChildAutoReap`); tenant data reaches the child only after the fork, in `WorkerInit` on its init socket, so the zygote holds none. The child then crosses the rest in this order (`zygote/child_boot.zig:Boot.run`):

| Step | What | Where | Why there |
| --- | --- | --- | --- |
| 1 | unshare user, mount and network namespaces, mapping uid and gid 0 to the server's own | `zygote/worker_boot/sandbox.zig:applyPostForkNamespaces` | `unshare(CLONE_NEWUSER)` refuses a multithreaded process, and engine work later restarts threads |
| 2 | receive `WorkerInit` within `WORKER_INIT_TIMEOUT_MS` | `child_boot.zig:Boot.receiveWorkerInit` | the child's wait has a bound of its own beside the launcher's window |
| 3 | map the page and send the child's own log lines into it, then close every descriptor but the init socket, the trace pipe and those `WorkerInit` brought, and check the message's fields | `zygote/log_sink.zig`, `child_boot.zig:closeUnexpectedWorkerFds`, `common/ipc/messages.zig:WorkerInit.validate` | nothing else the zygote holds reaches the worker, and no log line is lost; the receiver already held the egress descriptors to `flag_egress` and the boot token (`common/ipc/zygote_worker.zig:recvWorkerInit`) |
| 4 | check once that the child is the leaf's only member, that `memory.high`, `memory.max` and `memory.swap.max` (0, where the kernel accounts swap) hold what `WorkerInit`'s memory limit gives, and that `cpu.max` and `pids.max` hold the constants every worker gets (`common/cgroup.zig:worker.validateLimitsAt`), then keep `memory.events.local` and `memory.current` open | `worker_boot/cgroup.zig:validateAndOpenWorkerLeafAt` | no engine or tenant code runs under limits nobody set |
| 5 | prove the process single-threaded | `child_boot.zig` | the next privileges are per thread, and `/proc` is still there to read |
| 6 | set `RLIMIT_NOFILE` to `limits.DEFAULT_MAX_OPEN_FILES` and `RLIMIT_CORE` to 0, set no-new-privileges, make mounts private, mount a tmpfs of `WorkerInit`'s size with mode 0700 and `nosuid,nodev,noexec` over `/tmp` in the child's own mount namespace, lay out `tmp/` (bound onto itself), `var/` and `var/task/`, remount the root's mount read-only, `chroot` into it, enter `/var/task`, drop every capability | `worker_boot/sandbox.zig:applyPreThread`, `rootfs.build` | the namespace's capabilities allow the mounts and the chroot, and then go; the host never sees the mount, and every worker has a tmpfs of its own |
| 7 | resume the VM, pin the helper threads, point the engine's memory reading at the leaf ([boot.md](boot.md#the-child)) | `child_boot.zig` | threads may exist from here, and each inherits no capability |
| 8 | start the remaining threads ([boot.md](boot.md#the-child)) | `child_boot.zig` | the filter forbids creating threads |
| 9 | make the control socket nonblocking | `child_boot.zig` | the filter lets `fcntl` read flags and not set them |
| 10 | install the seccomp filter, as compiled, on every thread with `TSYNC` | `worker_boot/sandbox.zig:applySeccomp` | the last sandbox step, once every thread exists |
| 11 | close the trace write end, then register the definition's artifact, evaluate every route's entry and send `WorkerReady` ([boot.md](boot.md#the-boot-token-the-routes-entry-and-workerready)) | `child_boot.zig:Boot.closeTrace`, `worker/runtime/evaluations.zig:evaluateBootRoutes` | the first tenant code runs inside every layer and holds no trace pipe |

The host writes the leaf's limits before the fork and never reads them back: the child's check is the only read of those limits, and the zygote checks only that the leaf is an empty cgroup2 directory. The server reads a leaf's other files, and writes its `cgroup.kill`, only beneath the workers directory with no link followed (`host/cgroup_root.zig:openBeneath`). The root the child chroots into is read-only except `/tmp`: the root's mount carries `MS_RDONLY`, `tmp/` is a bind mount of its own on the same tmpfs under the same size limit, and the kernel refuses every write elsewhere with EROFS, for `node:fs` and for code that escapes the engine alike. The root's mount reports read-only, nosuid, nodev and noexec, and `/tmp`'s nosuid, nodev and noexec. Two layers keep the root as built, each tested alone: without `CAP_SYS_ADMIN` over its mount namespace the child cannot remount the root writable or `/tmp` read-only (`zygote/tests/sandbox.zig`, without a filter), and the filter admits no mount call. A rename between `/tmp` and the rest of the root fails with EXDEV. `node:fs` is closed in every process until `collo_vm_enable_node_fs_for_worker`, which only the child calls, after its filter: every operation checks a process-wide flag that call sets and fails with EPERM until then (`bindings/host_functions/node/fs.cpp`), so a binding installed anywhere else, the zygote included, reaches no file.

There is no PID namespace. Outside its user namespace a worker has the server's uid, the same as every other worker, so the seccomp filter is what keeps it from signalling or tracing them.

## The seccomp filter

The filter is an allowlist built at compile time (`zygote/worker_boot/sandbox.zig:security.buildTemplate`) and installed as it is, with no patch at install time; each argument policy fails the build on a target without its syscall, so every policy is in the program on every target. A foreign architecture kills the process, x32 calls fail on x86-64, and a syscall outside `security.allowed_syscalls` fails with EPERM. The list holds I/O on descriptors the worker already has (`read`, `write`, `recvmsg`, `sendmsg` and their kin), memory management including `mmap` and `mprotect`, futexes, clocks and `getrandom`, signal masks and handlers, `poll` and `ppoll`, the calls a thread makes at its own start (`rseq`, `set_robust_list` and `prctl(PR_SET_NAME)`), which must pass because a thread created before the filter can first run after it, and exit.

Arguments narrow the rest. `openat`, `mkdirat`, `unlinkat`, `renameat2`, `newfstatat` and `statx` work only relative to `AT_FDCWD`, which the chroot confines, and with fixed flag sets: `openat` takes the access mode, `O_CREAT`, `O_TRUNC`, `O_DIRECTORY` and `O_CLOEXEC` only, and `unlinkat` and `renameat2` take no flag; `fstat` on a descriptor passes in either spelling. `fcntl` takes only `F_GETFD`, `F_GETFL` and `F_GET_SEALS`. `prctl` takes only `PR_SET_NAME`, which renames the calling thread, so a worker can change nothing but what `/proc` shows of its own threads. An argument compared by value must have a zero high word, and a dirfd is matched on its low word, as the kernel reads it.

Absent from the list, and so denied, are `clone`, `clone3`, `fork` and `execve`, `socket` and `connect`, `io_uring_setup`, `io_uring_enter` and `io_uring_register`, `timerfd_create` and `timerfd_settime`, `kill` and `tgkill`, `ptrace` and `process_vm_readv`, every mount call (`mount`, `umount2`, `mount_setattr`, `open_tree`, `move_mount`, `fsopen`, `pivot_root`, `chroot`), `unshare` and `setns`, `chdir` and `fchdir`, `ftruncate`, `fchmod`, `linkat` and `symlinkat`, and every form of `dup`. `sendmsg` stays, so a worker can attach descriptors it holds to a packet, and every reader refuses such a packet. `mmap` with `PROT_EXEC` and `mprotect` stay because the JIT needs them, so code that escapes the engine can run native code inside its worker; the filter, the namespaces and the chroot bound what that code can ask of the kernel.

## The worker's loop

The worker's event loop waits in `ppoll` (`worker/scheduler/poll_backend.zig`): after each work item it polls without blocking, and with no work ready it blocks until a descriptor is ready or the earliest deadline passes (`worker/scheduler/loop.zig:run`), over at most five descriptors it already holds: the control socket, for input always and for room only while a response, the retirement notice or a `request_done` waits for it; the wakeup eventfd; the payload credit eventfd; and, while the worker is attached to an egress session, that session's completion eventfd and liveness pipe. Its timeout is the earliest of the next timer, the next request deadline, the deferred-work recheck and the idle work, the allocator cache release and the idle collection (`worker/scheduler/idle.zig`), so the worker holds no timerfd. While a gateway drain stopped at its batch bound, the wait polls with a zero timeout (`poll_backend.zig:PollBackend.egress_completion_debt`): the packets left in the completion ring have no eventfd count of their own, so a blocking wait could sleep with them unread. The filter admits `ppoll` with no argument policy, as for the sentinel's own wait: it reports readiness on the descriptors it is given and opens, creates and registers nothing. A hang-up of the control socket ends the loop, and a hang-up or error of the session's descriptors detaches the worker from the gateway. A worker whose definition has no network grant holds no egress descriptor and refuses an `egress_attach` (`worker/egress/state.zig:State.attach`), so its loop never watches one. The server ties each session to the worker's own wake set: a launch sends the session it built on its wake set with its `WorkerInit`, and the reattach pass takes a worker's control socket and wake set from one record under the pool's lock (`server/supervisor/supervisor.zig:StaleEgressFinder.visit`, `launcher.zig:reattachNextStale`). The worker refuses a session whose liveness pipe is not the one `WorkerInit` brought, compared by device and inode, before it detaches the session it holds (`worker/egress/state.zig:State.checkAttach`), so a session sent to the wrong worker's socket fails closed.

## What a worker cannot reach

Together the layers close these paths:

| Resource | What keeps a worker from it |
| --- | --- |
| the network | its own network namespace, which has no device or route (`zygote/worker_boot/sandbox.zig:namespaces`), and a filter without `socket` or `connect`; its one outbound path is its gateway session ([egress.md](egress.md)), and a worker whose definition has no network grant holds no egress descriptor at all |
| the machine's files | a private mount namespace, a tmpfs root it chroots into, read-only except `/tmp`, with no `/proc` or `/dev` inside, and path calls admitted only relative to `AT_FDCWD`; the kernel refuses every write outside `/tmp` with EROFS, and nothing left in the worker can clear the read-only flag, since it holds no capability and its filter admits no mount call; the filter admits no `mknodat`, `symlinkat`, `linkat` or `fchmodat` either, so the root holds only directories and regular files |
| programs, processes and threads | no `execve`, `clone`, `clone3` or `fork` in the filter, and `pids.max` on its cgroup |
| other processes | no `kill`, `tgkill`, `ptrace` or `process_vm_readv` in the filter, and no `/proc` to find them by |
| privileges | no-new-privileges and an empty capability set, in a user namespace that maps only the server's uid and gid and denies `setgroups` |
| memory and CPU | `memory.high`, `memory.max`, `memory.swap.max` at 0, `cpu.max` and `pids.max` on the cgroup it was born into, which the child checked against `WorkerInit`'s memory limit and the worker constants |
| the kernel's io_uring | none: no `io_uring_setup`, `io_uring_enter` or `io_uring_register` in the filter, and the loop waits in `ppoll` |
| other tenants' memory | a process of its own; it shares memory only with the server and the gateway, through the regions below |

## What a worker holds

| Descriptor or mapping | Comes from | The worker can |
| --- | --- | --- |
| control socket | the zygote's init socket pair | send response descriptors and each request's `request_done`, and attach descriptors the server refuses |
| payload memfd (`common/ipc/ingress_channel/payload_ring.zig`) | `WorkerInit`, size-sealed, closed once mapped | read and write both rings and all four cursors |
| state page (`common/worker_state/page/mapping.zig`) | `WorkerInit`, size-sealed, closed once mapped | write every byte |
| egress endpoint (`common/ipc/egress_shared/endpoint.zig`) | `WorkerInit` or `egress_attach`, region descriptors closed once mapped | write only the parts its half opens writable |
| egress wake descriptors | the worker's wake set, when its definition has a network grant: in `WorkerInit`, and after boot in each `egress_attach`, which a worker without a grant refuses, closing every descriptor it brought and leaving its loop | write both eventfds, hold the gateway's liveness pipe open |
| `memory.events.local`, `memory.current` | step 4 | read |
| definition artifact | `WorkerInit`, a sealed memfd mapped read-only for the worker's life; its descriptor closes once the boot evaluated every route | read; the engine wraps its sources in place, and the bridge reads it only through bounds-checked offsets |
| completion and credit eventfds, wake eventfd | `WorkerInit` and its own boot | write the eventfds |

## Surfaces and their readers

Every byte a worker can write in shared memory, and every packet it sends, reaches a reader that takes it as hostile:

| Surface | Reader, thread | Read-once path | A contradiction is |
| --- | --- | --- | --- |
| control socket | the worker's reader lane (`server/ingress/runner/worker_control.zig:drainWorkerControl`) | one `recvmsg` into the lane's buffer (`common/ipc/packet.zig:recvPacketWithFdsScratch`), decoded from it, any descriptor refused (`common/ipc/ingress_channel/receive.zig`) | a worker fault |
| `request_done` on the control socket | the reader lane, then the lane that owns its request (`server/ingress/runner/request_done.zig`) | `common/ipc/ingress_channel/framing.zig:validateDescriptor` and `decodeRequestDone` on the decoder's private copy: flags exactly `inline_bytes`, a 64-byte payload, `aux` and the reserved bytes zero, a known status and an HTTP status of 0 or 100 through 599; the reader decodes it into a `RequestDone`, whose status is the enum, a forwarded one travels decoded, and the owner acts on that record only for the request it names exactly | `ingress_channel_undecodable`; one that names a request the worker was not sent, `descriptor_names_no_request` |
| init socket at boot | the launcher | `zygote/host_client.zig:receiveWorkerInitOutcome` | a failed launch |
| `worker_to_server` payload ring | the reader lane | the lane's own read cursor, the worker's write cursor loaded once per operation, each payload checked against where the last one ended (`payload_ring.zig:SharedPayloadView`, `receive.zig:SharedPayloadHolds`), its bytes copied once by their consumer (`SharedPayloadView.heldPayload`) | `payload_ring_invalid` |
| `server_to_worker` read cursor | the lanes writing request bodies | loaded once per write and checked against the lane's own write cursor (`SharedPayloadView.loadCursors`) | `payload_ring_invalid` |
| lifecycle header | the death classification (`server/supervisor/worker_table.zig:Record.classifyDeath`), the launch of a child that ended before `WorkerReady` (`host/launch.zig:Machine.endedCause`) and the metrics pass (`Record.bootEndAttempt`) | `common/worker_state/page/snapshots.zig:LifecycleSnapshot`, tags kept raw and converted with `std.enums.fromInt`, the startup-end flag compared with 1 | an unknown state, read as none; a flag other than 1, read as not ended |
| live slots | the lane that ends a request without its `request_done` after its begin reached the worker (`worker_table.zig:Record.usageFloor`) | `page/mapping.zig:HostReaderView.loadLiveSlot` (`snapshots.zig:LiveSlotSnapshot.at`): one copy of the slot at the request's pool slot, read before the lane gives the pool slot back, the request id and generation matched | no match, so the floor carries no CPU from the slot |
| running-owner pair | the same floor (`Record.usageFloor`) | `snapshots.zig:RunningOwnerSnapshot.load`: the pair loaded between two reads of its sequence, its owner id compared with the request id | a moving sequence or another owner, so no CPU from the pair |
| boot stamps | the launcher at `WorkerReady` (`server/supervisor/launcher.zig:onReady`) | each stamp loaded once into the launch's trace, and combined only by saturating subtraction (`launcher.zig:childBootWorkNs`) | a wrong value, which reaches only that worker's launch trace and its requests' cold-start time |
| console ring | the metrics thread and the teardown (`server/analytics/logs.zig`) | frame headers copied once and checked (`page/console_ring.zig`) | `log_ring_corrupt` |
| console ring of a failed launch | the reaper, once, after the kill (`server/supervisor/reaper/root.zig:drainLaunchConsole`) | the same checked drain (`server/analytics/logs.zig:drainRing`), under the definition's name with worker id 0, every request id refused | a warning, and the ring's remaining lines are lost |
| egress command ring, upload pool, release queues | the gateway loop | [egress.md](egress.md#what-each-side-checks) | session removed or dropped |
| eventfds | the lanes and the gateway loop | drained as wakes, never read for content | `channel_failed` when a lane's read fails |
| liveness pipe | the gateway loop | polled for hang-up only (`egress/gateway/readiness.zig`) | session removed |
| trace pipe | the server's trace drain (`server/boot/trace_drain.zig`), only when the trace is logged | logged as text; written by the host, the zygote and each child's boot, never by tenant code | nothing |

The rule behind every row is the one `common/worker_state/page.zig` and `common/ipc/egress_shared.zig` state: a reader loads memory a worker can write once into a private copy, validates the copy and uses only the copy; a tag stays a raw integer until a checked conversion; and a cursor the reader owns lives in the reader's memory and reaches shared memory only as a store for the writer's room check, never loaded back (`page/mapping.zig:HostCursors`, `payload_ring.zig:SharedPayloadView.own_cursors`). The host holds a worker's page only as a `HostReaderView` (`page/mapping.zig`), an opaque mapping whose methods are those reads, so host code cannot load a page field itself. Payload and extent bytes stay in shared memory, so a worker can garble the bytes of its own requests and responses and never a length or a cursor.

A copy that passes is still the worker's claim. A worker's status and measures enter only the access record of the request whose `request_done` carried them, which the lane that holds the request builds with the identity the server holds (`server/ingress/runner/request_finish.zig:emitAccessRecord`). On its owner lane a `request_done` must name a live request of that lane, dispatched to the sending worker under the same request id and stream, whose begin reached the worker (`server/ingress/runner/request_done.zig:resolve`); the reader forwards one of another lane's request only while the worker's request table holds that request under the descriptor's key, and only once, marked once the post went in (`server/supervisor/request_table.zig:RequestTable.forwardCheck`, `markDoneForwarded`); and a floor reads only the live slot at the request's pool slot while it holds the request (`server/supervisor/worker_table.zig:Record.usageFloor`). An access record's duration comes from the lane's state, and its status is the status of the response head the lane queued for the worker, the worker's `http_status` counting only when no head went out, and the lane's 502 when a `request_done` left its stream unanswered (`request_finish.zig:workerDoneStatus`, `requestDoneLeftNoAnswer`); whether a response head went out is the lane's own HTTP/2 record (`server/ingress/runner/h2_worker_ipc.zig`).

The startup-end flag can only shorten boot egress. The host signs the token's deadline before the worker runs, and the server sends the token's `boot_ended` on the first 1 it reads, retrying a failed send without reading the flag again, so a worker compromised after an honest startup cannot take the end back; the gateway then also fails every fetch the token admitted that still runs ([egress.md](egress.md#the-token)).

Every SEQPACKET receive takes at most `common/ipc/messages.zig:max_fds_per_message` descriptors, close-on-exec, and closes every one it received when the kernel truncated the packet or its control data or when a zero-length datagram carried some (`common/ipc/packet.zig`). No packet from a worker may carry a descriptor: the reader faults the worker with `unexpected_descriptor` before it decodes such a packet (`server/ingress/runner/worker_control.zig`), and the decoders refuse one as well (`common/ipc/ingress_channel.zig`).

## Worker faults

`server/ingress/fault.zig` puts every failure into a domain: the connection, the worker, the lane or the server. A worker fault (`fault.zig:WorkerFaultReason`) is anything a worker's bytes or memory cause: a short, oversized or unknown packet, a packet with descriptors or with more descriptors than one receive holds, a zero-length datagram with descriptors, an undecodable ingress packet, a malformed `request_done` among them, a descriptor naming no request the worker was sent, an invalid response head or descriptor, contradictory payload-ring cursors, a failed allocation for its packet, a channel errno, a hang-up, an exit, a request outliving its deadline by `hard_timeout_grace_ns` (`server/supervisor/supervisor.zig:default_hard_timeout_grace_ns`), a VM thread past its owner's deadline, a broken console ring, an invalid retirement notice, an egress session no gateway could replace (`egress_session_failed`, recorded as `internal_error`), and one its gateway removed for a protocol violation (`egress_session_removed`, recorded as `crash`). Each callee's errors pass through a table that names all of them (`fault.zig:classifyWorkerError`), so an error a callee adds does not compile until someone gives it a domain, and the loop's handlers can return only `fault.zig:LaneFault` (`fault.zig:assertLoopHandlers`).

A fault costs the worker and its own requests. The lane takes the worker out of service (`server/supervisor/pool.zig:Pool.markDead`), answers each of its requests on that lane with 502, with 504 when the grace backstop found the request past its deadline, or with RST_STREAM once its head went out, and writes the reason into each access record. It tells the other lanes through `worker_died`, for which every lane's command queue keeps a reserve (`server/ingress/commands.zig`), and queues the retirement, whose kill, last console drain and cgroup removal run on the reaper and never on the lane (`server/ingress/runner/worker_fault.zig`). Failures on the server's side of the channel record `internal_error` and do not count against the tenant (`worker_fault.zig:errorCodeForFault`). The lane keeps serving every other connection, and a send that would block waits under the request's deadline without becoming a fault (`fault.zig:WorkerOutcome`).

A worker's death reaches its reader lane through its pidfd, which the kernel writes, so a worker can choose when to die and cannot forge a death (`exited`), or through the hang-up of its control socket (`peer_closed`). When its cgroup counts it past `memory.high`, its configured limit, its sentinel thread writes the dead state with reason `memory` on the page and exits the process at once (`worker/runtime/sentinel.zig`), and `memory.max`, 115% of that limit (`common/cgroup.zig:maxBytes`), is the kernel's backstop; either way the death costs only that worker's requests.

The gateway contains its sessions the same way: a session it removes takes only that worker's fetches ([egress.md](egress.md#sessions)), and it reports each removal with its cause (`egress/gateway/control.zig:SessionRemovedCause`). A `protocol_violation`, a command ring or a command that fails its checks, an extent the pools reject or a completion ring left unread, retires the worker as `egress_session_removed`, which records `crash`, the tenant's fault, on its requests' records; the lanes still read its ingress output to the end, since it broke only the egress protocol. A `liveness_closed` is left to the worker's pidfd and control socket, which record its death when it exited. A live worker closes its end of the pipe only by detaching on its own, which only a gateway packet or shared region a gateway defect produced makes it do (`worker/egress/gateway_runtime.zig:detachForGatewayFault`); it then asks to be retired with `worker_retiring` reason `egress_detached`, finishes its requests in flight and is never attached again, so a gateway defect retires the workers it touches without failing their requests. Whichever report reaches the server first, a memory death the worker met first wins: the lanes record `memory` for both egress reasons when its page or leaf shows one (`server/ingress/runner/worker_fault.zig:deathStatus`), and the reaper's line for it says the memory ending, or `crash` when its pidfd already reads exited (`server/supervisor/reaper/root.zig`).

## What the gateway trusts

The gateway holds the network capability, so it trusts only its control socket from the server, whose hello and attaches it decodes whole, and nothing a worker sends. It assigns session ids itself, attaches each session under the security cell the server named, and believes nothing in a fetch start before `common/ipc/egress_token.zig:verify` accepts the token under the hello's key; the session, request, deadline and policy of a fetch come from the verified token alone (`egress/gateway/runtime/command_flow.zig`). A worker's fetch ids mean nothing outside its session (`egress/gateway/fetch_table.zig`), and pools, TLS sessions and shards are keyed by cell and policy, so one definition's connections never serve another (`egress/gateway/shard.zig:hashFetch`).

What bounds one worker there is its session's active-fetch cap, which counts a fetch until its terminal packet and a fetch the gateway ended until the engine let go of it, its cell's cap, its tokens' deadlines, its pooled upload bytes and the gateway's upload budget; a refused command fails only its fetch and allocates nothing. [egress.md](egress.md#refusals-and-removal) lists the refusals and the removals. The gateway is confined as well (`egress/gateway/sandbox.zig`): its own user and mount namespaces, a read-only tmpfs root holding only the trust store and the resolver files, no capability, no-new-privileges, Landlock where the kernel has it, and a seccomp blocklist installed once its threads exist.

| `server and host code hold a worker's page only as its read-only host view` | `runtime/src/server` and `runtime/src/host` outside tests name neither `WorkerWriterView` nor `mapWorkerWriter`; they hold the page as `common/worker_state/page/mapping.zig:HostReaderView`, an opaque mapping whose methods load each field once into a copy (the lifecycle, owner and running-owner snapshots, a live slot, the console drain and its drop counters, a boot stamp, the benchmark record), so the compiler keeps them from loading a page field themselves; a second test lists the bypasses it must catch and the reads it must pass |

Each gate matches text and catches only the shapes it searches for: the page gate catches the worker's view named or mapped in `runtime/src/server` and `runtime/src/host`, and a `@ptrCast` of the host view's handle would pass it. No gate covers the gateway's reads of egress memory, the ingress payload rings or the seccomp allowlist; their layouts are pinned beside each struct and under `runtime/tests/contracts/`, and the module suites test their behavior, such as `zygote/tests/sandbox.zig` for the filter and `common/tests/ipc/slot_snapshot.zig` for the slot copy.

## Open points

A worker reaches its definition's grants. A worker that runs native code can spend the token of every request in flight in its process, since tokens are not kept apart inside one worker (`egress_token.zig`), and its boot token names the union of its routes' grants (`server/routes/network.zig`), so any route's code that escapes the engine reaches every origin some route of its definition is granted.

A worker reaches its own tokens. A token admits fetches until its deadline, up to `common/limits/server.zig:request_timeout_ms_max` after admission, under its session's `max_active_fetches_per_worker_session` concurrent fetches; the gateway keeps no count per token, and the per-request fetch limit is the worker's own (`worker/egress/fetch_runtime.zig`), so a dishonest worker is bounded by that cap and the deadlines of the tokens it kept. Each of those fetches can be a pooled upload whose assembly buffer and start copies the gateway allocates at admission, up to 32 MiB a buffer and at most 64 MiB per session counted with the copies, out of a 512 MiB upload budget every tenant shares, freed at the token's deadline at the latest (`egress/gateway/runtime/upload_flow.zig`, `egress/gateway/containment.zig:upload_memory`). Eight sessions at that cap fill the budget and make every other session's pooled starts fail meanwhile.

A worker reaches the command queues of the lanes that hold its requests, for those requests only and within its forwarding window. Its reader checks each descriptor that names another lane against the worker's request table before forwarding it (`server/supervisor/request_table.zig:RequestTable.forwardCheck`): one for a request the worker holds under another key faults the worker, and one for a request it no longer holds drops at the reader. A forwarded response descriptor and the answer for its ring payload take only places the owner reserves for each worker entry (`server/ingress/commands.zig:Command.placement`, `server/ingress/lane.zig:obligationReserve`), and at most `common/limits/ingress.zig:forwarded_commands_per_worker_max` of one worker's forwarded commands wait in lanes' queues at once: past that, its reader stops receiving from its control socket until the owners apply them (`server/ingress/runner/h2_worker_ipc.zig:acquireForwardUnit`, `windowHasRoom`). A worker that writes faster than its lanes apply therefore delays only its own responses. One residue stays, as `commands.zig` says: when a lane leaves an earlier command of a worker entry unprocessed while that entry's worker is launched, dies and is retired again, the entry's obligations pass their share, and a forwarded descriptor that finds the reserve full meanwhile is refused and drops the rest of its response, which takes a lane stalled for a whole worker lifetime. A request's `request_done` takes no unit of the window: it travels decoded on a place the owner reserves for each request in flight, and is lost only when the owner lane has stopped or that residue has filled its reserve and its ordinary places, which leaves the request to its owner's grace backstop ([request.md](request.md#the-reader-lane-and-forwarding)). A lane that holds a request but does not read its worker can still fault the worker at that backstop when the reader has not yet read a `request_done` sent in time ([request.md](request.md#open-points)).

A worker reaches the server's standard error through its console ring. The runtime's own log lines travel there flagged `LogLineFlags.runtime` (`zygote/log_sink.zig`), and the server writes such a line to its stderr instead of the tenant's log (`server/analytics/logs.zig`); the flag is the worker's claim, so a worker can write lines into the operator's log at the rate its console ring drains, each under its own identity, and none as another worker or as the server.

A worker can write its completion, credit and egress command eventfds at will. Each write costs its reader lane or the gateway's single loop thread a pass over that worker, and nothing bounds the rate.

The CPU, timing and byte counts a worker reports enter only its own records, and they remain its claim (`server/ingress/runner/request_done.zig:resolve`, `server/supervisor/request_table.zig:RequestTable.forwardCheck`, `server/supervisor/worker_table.zig:Record.usageFloor`). The `http_status` it reports enters a record only for a request whose response head never went out (`server/ingress/runner/request_finish.zig:workerDoneStatus`). A worker can also end its own request with `internal_error`, the code the server uses for its own failures; on a dispatched request's record, `origin` tells the two apart.
