# Egress

This reference follows an outbound `fetch()` from a worker to the origin and back: the egress gateway process and its sandbox, the control wire between it and the server, the capability token that admits each fetch, the shared-memory session between a worker and the gateway, and what each side checks and bounds on the way. The mechanics belong to the code and its `//!` headers: the token to `common/ipc/egress_token.zig`, the session's memory to `common/ipc/egress_shared/`, the fetch messages to `common/ipc/egress.zig`, the network policies to `common/network/`, the gateway process to `egress/gateway/`, the server's side to `server/gateway/`, `server/routes/network.zig` and `server/supervisor/launcher.zig`, the worker's side to `worker/egress/`, the response queue the two share to `egress/core/`, and the outbound client to `egress/client/`. Paths are relative to `runtime/src/`, a reference reads `file.zig:symbol`, and the code wins wherever this page disagrees with it. [security.md](security.md) places the gateway inside a worker's trust boundary.

## Processes and threads

The gateway is one process per node and the only one that opens outbound connections. Its main thread runs the loop (`egress/gateway/runtime/root.zig:Gateway.serve`) and owns the worker sessions (`egress/gateway/sessions.zig`), the one table of fetches (`egress/gateway/fetch_table.zig`), the pooled uploads still assembling, the control socket and what the server's hello brought (`egress/gateway/runtime/control_flow.zig:HelloState`). Each shard adds an engine (`egress/client/engine/`) whose one owner thread runs every fetch of the shard on one io_uring data driver: its DNS lookups through the shard's cache, its TCP connects as Happy Eyeballs attempts the driver watches, its TLS handshakes stepped on the driver's completions, its HTTP/2 streams and its HTTP/1 exchanges. The cache's two resolver threads are the shard's only other threads and the only ones that block, in `getaddrinfo`. Of what the gateway loop also reaches, the engine's threads touch only tasks, response queues, the shard's counting allocator, its ready ring and its wake eventfd. The gateway loop reaches the owner only through what the engine's mutex guards, and never waits for it: a submit or a cancel links the task into a list, and a body credit merges into the credit source of the stream or HTTP/1 fetch that issued it (`egress/client/engine/root.zig`, `credit_sources.zig`).

On the server, `server/gateway/manager.zig:Manager` holds the current gateway. The thread that spawns it reads its ready report and sends the hello (`server/gateway/process.zig:spawn`), one reader thread per gateway receives its acks and removal reports (`server/gateway/control_client.zig:Client`), each ingress lane mints tokens from its lease (`server/gateway/lease.zig:Lease`), the metrics thread sends the end of each boot token (`manager.zig:Manager.endBoot`), and the launcher thread attaches and reattaches sessions and retires a worker whose session a gateway removed for a protocol violation (`server/supervisor/launcher.zig`). A worker runs its side on its event loop thread (`worker/egress/state.zig`).

## The gateway process

`server/gateway/process.zig:spawn` runs the server's binary as `egress/gateway/launch.zig:process_name` with no argument, the control socket at `launch.zig:inherited_control_fd` and an environment of `process.zig:inherited_environment` alone (`RES_OPTIONS`, `LOCALDOMAIN`, `TZ`), so nothing but the hello configures the gateway. It gives the gateway `OOM_SCORE_ADJ_EGRESS_GATEWAY` (`common/limits/process.zig`), waits up to `process.zig:GATEWAY_READY_TIMEOUT_MS` for `gateway_ready`, and sends the hello before the control reader starts, so the hello is the first packet the gateway reads.

The boot order is fixed (`egress/gateway/runtime/root.zig:run`). The sizing plan is computed while `/proc` is visible; the decoders are linked into the binary, so nothing loads from the machine. `egress/gateway/sandbox.zig:applyProcessBaseline` then checks that the process is single-threaded, enters a user and a mount namespace and keeps the server's network namespace, lowers `RLIMIT_CORE` to 0, `RLIMIT_NOFILE` to the plan's open-file limit (`egress/gateway/sizing.zig:openFilesLimit`) and `RLIMIT_NPROC` to `EGRESS_GATEWAY_TASKS_MAX`, and leaves the address space unlimited, since budgeted allocators bound the gateway's memory (`egress/gateway/containment.zig`). It then mounts a tmpfs over `sandbox.zig:staging_path` with read-only binds of the first CA bundle among `trust_store_sources` and of `resolver_files`, remounts it read-only and chroots into it, drops every capability, sets no-new-privileges and applies a Landlock ruleset that denies every write where the kernel has Landlock. The trust store loads next, `Gateway.init` builds the shards and the readiness ring, `Gateway.startShards` starts the shards' threads and polls their wake eventfds, the seccomp filter goes onto every thread with `TSYNC` (`sandbox.zig:applySeccompAfterThreadsStarted`), and `gateway_ready` comes last, so the server records only a fully sandboxed gateway.

The gateway exits through `_exit` as soon as its loop returns (`egress/gateway/root.zig:runFromInheritedControlFd`): with status 0 after the server's shutdown or hang-up, and with status 1 after one line naming the error. Nothing is torn down first, since engine threads may still run and exit handlers could hang beside them; the kernel releases what the process holds, and the server waits for the exit on the gateway's pidfd for a bounded time before SIGKILL (`server/gateway/process.zig`).

The gateway's filter is a blocklist (`sandbox.zig:blocked_syscalls`). It kills a foreign architecture, fails x32 calls on x86-64, and answers EPERM to `io_uring_setup` and `io_uring_register`, `bind`, `listen` and `accept`, `memfd_create`, every form of `dup` including `fcntl(F_DUPFD)`, `clone`, `fork` and `execve`, namespace and mount calls, `ptrace` and `process_vm_readv`, `bpf`, `kill` and its relatives, and `socket(AF_UNIX)`, since abstract Unix sockets belong to the network namespace it shares with the server. Since the filter forbids new threads and rings, a shard restarts on the threads and rings its first start created (`egress/gateway/runtime/shard_flow.zig:superviseShardFailure`), and a dead ring ends the process.

The hello (`egress/gateway/control.zig:HelloHeader`) carries a 32-byte key drawn for that gateway alone (`common/ipc/egress_token.zig:Key.random`, called from `server/gateway/manager.zig:Manager.spawnRecord`) and the length of the policy image, whose memfd, sealed against writes and resizes, is the packet's one descriptor. The server compiles every route's `network` grant into that image once at boot and lends it to each hello (`server/routes/network.zig`, `manager.zig:Config.policy_image`); a request token names its route's policy by id and a boot token its definition's ([The token](#the-token)). The gateway decodes the hello whole: one descriptor, a nonzero key, zero reserved bytes and an image length of 1 to `common/network/table.zig:image_bytes_max` (`control.zig:decodeHello`). It reads the image only from a memfd that carries the seals and holds exactly that length, and decodes it with every check of `table.zig` (`control_flow.zig:readPolicyImage`); an image it refuses, which only a server bug sends, ends the gateway. Until the hello arrives the gateway holds the zero key, which verifies nothing, and takes only the hello and shutdown; any other packet first, or a second hello, ends the gateway (`egress/gateway/runtime/control_flow.zig:handleControl`). Both sides scrub the key from their buffers once it is copied (`control.zig:sendHello`, `control_flow.zig:handleControl`), and the key and the decoded table never change for the life of the gateway.

## The control wire

One SEQPACKET socket per gateway carries the protocol (`egress/gateway/control.zig`). Each packet opens with `control.zig:Header`, the magic `CEB1` and a kind, and every decoder takes exact lengths and known kinds only; both processes compile the file, so a packet that does not decode is corruption.

| Kind | Sender, thread | Carries | Receiver's check |
| --- | --- | --- | --- |
| `gateway_ready` | gateway loop, last boot step | nothing | `control.zig:decodeGatewayReady`, read by `process.zig:recvGatewayReadyBeforeTimeout` |
| `hello` | the server's spawning thread, once | key, image length and the policy image's memfd | `control.zig:decodeHello`, the image's seals, length and decoding (`control_flow.zig:readPolicyImage`), and the order in `control_flow.zig:handleControl` |
| `attach_worker` | launcher, through `control_client.zig:Client.attachWorker` | request id, security cell, the gateway's half of a session | exact length and `shared_fd_count` descriptors (`control.zig:decode`), then the endpoint's map checks |
| `attach_worker_ack` | gateway loop | status, request id, session id | `control.zig:decodeAttachAck`, and it must name the waiting attach (`control_client.zig:Client.completeAttachAck`) |
| `boot_ended` | the metrics thread, through `manager.zig:Manager.endBoot` | session id | `control.zig:decode` (`decodeBootEnded`): exact length, no descriptor, a nonzero session |
| `session_removed` | gateway loop | session id and the cause, `liveness_closed` or `protocol_violation` (`control.zig:SessionRemovedCause`) | `control.zig:decodeGatewayToServerPacket`: exact length, a nonzero id, a named cause and a zero reserved word |
| `shutdown` | server, `process.zig:GatewayProcess.deinit` | nothing | no descriptors, exact length |

The kinds are numbered 1 to 7 in that order. The gateway's end is nonblocking. An ack or removal report that finds the socket full waits in a FIFO of `control_flow.zig:pending_control_packet_capacity`, and later packets queue behind it (`control_flow.zig:sendOrQueueControlPacket`). An ack that can be neither sent nor queued removes the session it acknowledged, unreported, since the server never learned its id; a removal report that can be neither sent nor queued ends the gateway, so the server never keeps a worker it believes attached. A server hang-up ends the loop.

On the server the first failure of the channel stops the client for good (`control_client.zig:Client.failChannel`): a send error, a send or ack that misses `control_client.zig:control_timeout_ms`, and every reader error, which covers the hang-up of an exiting gateway, a packet that does not decode and an ack naming no waiting attach. Its callback, `manager.zig:Manager.retireAfterFailure`, takes the record out of `current`, sends SIGKILL and tells the launcher (`manager.zig:Deps.gatewayLost`). A refused attach, which the gateway sends once it holds `Plan.sessions_max` sessions or when the session's memory does not map or register, fails that call alone.

## Shards, engines and readiness

`egress/gateway/sizing.zig:Plan.compute` takes the shard count from `sizing.zig:defaultShardCountForCpus`, half the CPUs that affinity and the cgroup quota allow, at least 2 and at most `shards_max` (8), or 1 on one CPU; lowers it, never below 2, while fewer than `max(cpus, sessions_floor_min)` sessions would fit the open-file limit; and caps the sessions at what that limit holds beside its fixed reserves. Nothing else is planned. The server reads only `sizing.zig:sessions_max`, the most sessions any gateway holds (`launcher.zig:lost_sessions_max`). Each shard is an engine with a counting allocator budgeted at `egress/gateway/containment.zig:shard_memory`, so a runaway shard fails its own allocations (`egress/gateway/counting_allocator.zig`).

A fetch runs on the shard `shard.zig:hashFetch` picks from its pool key (the security cell and `policy.zig:poolPolicyId` of the policy its token names), its scheme and its canonical origin, so a cell's fetches to one origin under one policy share that shard's connections. The engine hands the same pair to the transport with the fetch (`engine.zig:Engine.submit`), and it is part of the key of every pooled connection, shared dial and TLS session (`egress/client/transport/request/plan.zig:OriginKey`), so a connection opened for one definition or one policy never serves another.

Fetches that may speak HTTP/2 to one origin key wait on one shared dial, which the origin's record holds; an HTTP/1 fetch dials alone and offers http/1.1 only, since its connection is never shared (`egress/client/engine/dial.zig`). A dial resolves through the shard's DNS cache, checks every resolved address against the hop's admission before any socket opens, races nonblocking TCP connects (`egress/client/transport/connect.zig`: IPv6 and IPv4 alternating, IPv6 first, a new attempt every 250 ms while one is pending, at most four at once) and, for HTTPS, steps the TLS handshake on the driver's completions. Each phase has the fetch's socket timeout as its stall deadline, and each waiting fetch also fails at its own request deadline. ALPN h2 makes the wire an HTTP/2 pool entry for every waiting fetch; http/1.1 gives it to the first waiting fetch and marks the origin, so its next fetches go straight to HTTP/1. A cancel ends a fetch wherever it is held and abandons a dial nobody else waits on, and a stop settles every fetch in every phase before it returns.

Each connection's bytes move through one `egress/client/transport/wire.zig:Wire`: a socket, a 16 KiB receive buffer, a send queue and, for HTTPS, BoringSSL transforming bytes over memory BIOs; plain HTTP is the identity transform. The owner's data driver keeps at most one receive and one send in flight per wire and marks every receive or send failure on the wire as it learns of it, and both protocols read and write plaintext through the wire, which says what it needs from the network next. Bytes a wire holds on this side, queued sends plus TLS ciphertext the read BIO has not taken, are capped at `transport/config.zig:Config.wire_buffer_bytes`, and a TLS wire reports the end of the stream at the socket's EOF whether or not a close_notify came first. An HTTP/1 wire is pooled only when its response ended by its own framing and the wire holds no unread byte and saw neither EOF nor a failed receive or send (`Wire.cleanForReuse`), since a leftover byte would read as the next response's head. The engine keeps a receive armed on each idle pooled wire, and before a lease the driver brings the wire up to date with its socket (`egress/client/io/bio_data.zig:Driver.refreshIdleWire`), so a close or a stray byte that arrived while it idled makes it unclean, and the pool drops it (`transport/http1/root.zig:Http1Pool.evictUnusable`). The driver's drains flush the completion queue's overflow list whenever a batch empties the ring (`Driver.flushOverflow`), so a drain that ends leaves no completion behind in either place, and a registration whose wire the kernel may still write is never freed under it: one whose cancel the kernel never confirmed, whose cancel's terminals could not be drained yet, or on a dead ring is quarantined, owned by the driver, until its terminals arrive or the ring is torn down (`Driver.quarantine`). A ring counts as dead only when `io_uring_enter` fails with EBADF, EBADFD, ENXIO or EOPNOTSUPP. An HPACK coder holds only its ls-hpack handle and table state (`bindings/hpack/root.zig`); every call takes the caller's scratch, which each shard's owner keeps once (`transport/h2/codec/session.zig:HpackScratch`). A response's headers are decoded once and copied once into the task's result (`egress/client/task.zig:Task.copyResponseHeaders`), and the client counts no bytes for any record.

An error confined to one fetch's publication fails that fetch (`shard_flow.zig:isFetchDemotableError`); any other error out of a collection pass, a hung-up shard wake eventfd or an owner-loop fault the engine latched goes to `egress/gateway/runtime/shard_flow.zig:superviseShardFailure`, which stops the engine, ends every fetch the shard ran with an error and starts the engine again on the same threads and rings. Pooled uploads still assembling are left alone and reach the restarted engine once their bodies arrive (`fetch_flow.zig:endShardFetches`). A shard that would exceed `containment.zig:shard_restart` restarts in its window, or whose restart fails, ends the gateway, and the server spawns another. An engine run whose data wait fails, a dead ring, ends with every fetch settled and the owner fault latched, and the restart's start then fails with `error.EgressDataRingDead`, which ends the gateway (`egress/client/engine/root.zig`). Each start begins a new engine run: a credit names the run that issued it, the gateway drops a credit of a run that ended (`engine.zig:Engine.releaseCredit`), and the engine's credit source ids run on across runs (`egress/client/engine/credit_sources.zig`), so a credit a worker held across a restart reaches no stream of the new run.

The loop waits on one io_uring (`egress/gateway/readiness.zig:Backend`) built before seccomp and restricted to `POLL_ADD`, `POLL_REMOVE` and `TIMEOUT`, with a `readiness.zig:wait_tick_ns` timeout so its periodic work runs when nothing is ready. It polls the control socket on every pass, each shard's wake eventfd from `Gateway.startShards`, and each session's command eventfd and liveness descriptor, the latter for hang-up only, from the session's attach until its removal. Polls are one-shot, and `Backend.rearm` adds again only the polls that completed in the last wait, so a pass costs work for what woke it, never for every session. A collection pass takes at most `shard_flow.zig:ready_event_collect_max` ready tokens, each naming its fetch's record by handle (`egress/gateway/ready_scan.zig`), and `egress/gateway/publisher.zig` publishes a body batch whole or not at all.

## Backpressure

Before it pulls a chunk from a fetch's response queue, the body drain checks the worker's free pool blocks and completion-ring bytes against the worst case of what it holds unpublished plus one more pull (`egress/gateway/runtime/body_pump.zig`): a pull is destructive, so a chunk pulled without room would be lost. A drain that finds no room stops with the queue armed, and flow control holds the origin back. One short of pool room resumes with the worker's next release, which queues the session so its fetches are pumped before the next wait (`release_flow.zig`, `session_flow.zig:processAttention`); one short of completion-ring room keeps its session in the attention list until the ring has room (`session_flow.zig:awaitRingRoom`). A full body pool means a slow reader, while a completion ring at `session_flow.zig:hard_percent` (95%) means a worker that stopped reading completions, which breaks the protocol: the session stays in the attention list, is measured on every pass, at most `readiness.zig:wait_tick_ns` apart, and is dropped after `hard_drop_grace_ns` (1 s) at that mark. A response head goes out only when the ring keeps `session_flow.zig:head_reserve_bytes` free below the hard mark behind it, and otherwise waits with its fetch until the ring has room (`session_flow.zig:queueHead`, `fetch_table.zig:Fetch.head_waits_room`). The reserve holds the terminal packet of every fetch an honest worker counts and every body batch its pool can back (`egress/gateway/publisher.zig:unread_batch_bytes_max`), and a comptime check fits it with the largest head into an empty ring, so an honest worker's ring never reaches the hard mark however long it reads nothing. A terminal packet's size is bounded because the codec caps a fetch error's message at `common/ipc/fetch_limits.zig:response_error_message_bytes_max`. A publication that still finds the pool or the ring full fails its fetch. On the worker, a full command ring or upload pool parks the task in `worker/egress/state.zig:State.pending_uploads`; starts and upload batches leave `common/ipc/egress_shared/packet_ring.zig:command_control_reserve_bytes` free so that stops still fit, and the gateway writes the worker's completion eventfd after returning upload extents and after a drain that found new drops (`session_flow.zig:wakeWorkerAfterCommandDrops`).

## The token

A token is 56 bytes (`common/ipc/egress_token.zig:Token`); its tag is the first 16 bytes of HMAC-SHA256 over the 40 bytes before it, under the gateway's key.

| Field | Offset | Holds |
| --- | --- | --- |
| `kind` | 0 | 1 for a request token, 2 for a boot token; 0 names no kind, so `egress_token.zig:none` is no token |
| `reserved0` | 1 | zero |
| `policy_id` | 2 | the policy in the hello's image: the request's route's, or for a boot token the worker definition's |
| `reserved1` | 4 | zero; with `reserved0` it keeps the 64-bit fields aligned |
| `session_id` | 8 | the session it was minted for |
| `request_id`, `request_generation` | 16, 24 | the request, both 0 for a boot token |
| `deadline_monotonic_ns` | 32 | the CLOCK_MONOTONIC instant from which it admits nothing |
| `tag` | 40 | the MAC |

An ingress lane mints a request token for each dispatch to a worker that has a session. `server/ingress/runner/dispatch.zig:requestTokenFields` takes the request's deadline fixed at admission and the policy of the request's route (`server/routes/network.zig:NetworkPolicies.routePolicy`), and `lease.zig:Lease.mint` signs it, or returns `none` when the lease holds no gateway or another gateway than the worker's session. The lease holds the gateway's generation and a copy of its key, and no descriptor of it, and is renewed only when `Manager.currentGeneration` moves, which the lane loads once per loop pass (`server/ingress/runner/ring_driver.zig:renewEgressLease`), so the request path takes no lock and sends nothing to the gateway. The worker copies the token from its `DispatchWork` into every fetch start and never reads it (`common/ipc/dispatch.zig`).

The boot token admits the fetches of module top-level code while the worker's startup evaluations run, including top-level awaits still pending after `WorkerReady`. `server/supervisor/worker_factory.zig:bootEgress` gives it the launch's session and the definition's boot policy, the union of its routes' grants (`server/routes/network.zig:NetworkPolicies.bootPolicy`), and `host/launch.zig:Machine.mintBootToken` signs it just before `WorkerInit` goes out, with the init deadline plus `common/limits/process.zig:MODULE_EVAL_BUDGET_NS` as its deadline (`bootEgressDeadline`), 13 seconds after the send for the server's launches. The machine keeps no copy of the key, and the launcher scrubs its own (`server/supervisor/launcher.zig:receiveForkReply`). Only the evaluations the boot opens copy it (`worker/runtime/evaluations.zig`), and the boot opens every evaluation a worker has. When the last of them closes, the worker sets `startup_evaluations_ended` on its lifecycle page, and the server's metrics pass sends the token's end, a `boot_ended` packet naming the session, to its session's gateway (`server/supervisor/supervisor.zig:Supervisor.progressBootEgress`, `manager.zig:Manager.endBoot`), again on each later pass until the send goes out, that gateway is gone or the deadline passes. The gateway sets the session's `boot_ended`, after which its boot token admits nothing, and fails every fetch that token admitted that still runs or assembles its upload (`egress/gateway/runtime/fetch_flow.zig:endBootFetches`), so a worker compromised after its startup keeps nothing its boot token started. The flag can only end the token early: a worker that never sets it keeps the token until its deadline, and neither readiness nor a reattach mints or extends one. A detach leaves the worker's copies in place: the next gateway refuses the old token as forged, as it does a request token minted before the replacement.

`egress_token.zig:verify` compares the tag first, in constant time, and reads the kind only once the tag vouched for it, so a forger cannot learn which field it got wrong; the decoder refuses `none` and reads no other byte (`common/ipc/egress.zig:decodeFetchStart`). The zero key verifies nothing, and each gateway has a key of its own, so the tokens of an earlier gateway fail as forged.

The gateway keeps nothing per token. A token admits fetches until its deadline under its session's and its cell's active-fetch caps, and each fetch runs under that deadline as its own (`egress/client/transport/config.zig:Config.request_deadline_mono_ns`). The per-request fetch limit is the worker's: it counts the fetches started under each token and stops a request's fetches at its cleanup (`worker/egress/fetch_runtime.zig`, `worker/egress/task_runtime.zig:cancelForRequest`).

## Sessions

A worker has one wake set for its life (`common/ipc/egress_shared/session_fds.zig:WakeSet`): the eventfd that wakes the gateway, the one that wakes the worker, and the read ends of two liveness pipes. Every session of the worker is new region memfds on that set (`session_fds.zig:createSessionForWorker`), and the worker's loop watches the completion eventfd and liveness pipe of whatever session it holds at each wait (`worker/scheduler/poll_backend.zig`). The set holds no write end: each session opens its two write ends from the read ends through `/proc/self/fd`, and the server closes its copies once each side has its own (`session_fds.zig:SessionFds.takeWorkerHalf`), so the gateway's death hangs up the worker's pipe and the worker's exit or detach hangs up the gateway's. A new session opens its write end of the worker's pipe before its `egress_attach` is sent, so the hang-up a lost session left there has ended before the worker can read the attach, and no wait of the worker reports both (`server/supervisor/launcher.zig`).

A session has four regions of four size-sealed memfds each, the meta, the producer state, the consumer state and the data (`common/ipc/egress_shared/region.zig`), so a side's half is 16 region descriptors and 4 wake descriptors (`session_fds.zig:shared_fd_count`). Every memfd also gets a read-only reopen, each side receives a writable descriptor only for what it writes (`SessionFds.rawForGateway`, `SessionFds.rawForWorker`), and mapping checks each descriptor's access mode, seals and size and the meta's magic, version, role and capacity (`common/ipc/egress_shared/endpoint.zig`), so the kernel refuses a side's writes to the other side's state.

| Region | Size | Producer | The worker writes | The gateway writes |
| --- | --- | --- | --- | --- |
| command ring | `packet_ring.zig:command_ring_capacity` | worker | producer state, data | meta, consumer state |
| completion ring | `packet_ring.zig:completion_ring_capacity` | gateway | consumer state | meta, producer state, data |
| body pool | `body_pool.zig:body_pool_capacity` | gateway | consumer state, its release queue | meta, producer state, consumer state, data |
| upload pool | `body_pool.zig:body_pool_capacity` | worker | producer state, consumer state, data | meta, consumer state, its release queue |

A launch attaches a session only when the worker's definition has a grant, a boot policy other than 0 (`worker_factory.zig:definitionHasEgressGrant`). `manager.zig:Manager.attachWorker` builds the session on the worker's wake set and sends the gateway's half under the security cell, the first 16 bytes of SHA-256 over a label and the definition's name (`manager.zig:securityCellIdForDefinition`). The gateway maps its half (`common/ipc/egress_shared/endpoint.zig:mapEndpointTakeForGateway`), stamps the session id it assigned into the four metas and answers (`egress/gateway/runtime/session_flow.zig:attachSession`, `egress/gateway/sessions.zig:Registry.attach`); ids count up from 1 and never repeat within one gateway, so no later session is admitted under an earlier one's tokens. `WorkerInit` carries the worker's half with the boot token. A launch whose attach fails on the control channel, on a gateway spawn or on descriptors the server could not create boots its child detached with its wake descriptors only (`host/launch.zig:LaunchEgress.detached`), and the launcher attaches it after its publish; the gateway's refusal fails the launch with `egress_attach`, and a gateway that is not wired or an incomplete attachment fails it with `egress_gateway_required` (`server/supervisor/launcher.zig:attachForLaunch`).

The gateway removes a session on its own when the worker's liveness pipe hangs up, when its command ring or a command breaks the protocol, and at the end of the pass when it was marked for drop ([Refusals and removal](#refusals-and-removal), `egress/gateway/runtime/session_flow.zig:removeSession`, `removeDroppedSessions`): it ends the session's fetches without a packet, canceling each one its engine still runs, removes the session's polls and reports `session_removed` with its cause. A hang-up is `liveness_closed`, since the pipe cannot tell the worker's exit from a detach the worker made on its own; everything else is `protocol_violation`, something the worker sent or left unread. The control reader passes the report to the launcher (`manager.zig:Deps.sessionLost`), and nothing replaces the removed session (`launcher.zig:dropLostSession`). A launch that held it fails with `egress_attach` at its `WorkerReady`, whatever the cause. A live worker's `liveness_closed` is left to its pidfd and control socket, which record how it died ([memory-pressure.md](memory-pressure.md#a-memory-death)), and a worker that detached on its own asks to be retired itself ([below](#sessions)). Only a `protocol_violation` retires the worker (`server/supervisor/supervisor.zig:Supervisor.retireEgressSession`): departure `egress_removed`, the lanes told `egress_session_removed`, which records `crash`, the tenant's fault, and the worker's line in `workers.jsonl` ends `egress_session_removed` unless the reaper finds that the worker met a memory death or had already exited ([scheduler.md](scheduler.md#the-reaper)).

A gateway that dies hangs up every attached worker's liveness pipe. The worker's wait reports `egress_closed`, and `worker/egress/gateway_runtime.zig:disconnectWithReason` fails every active fetch, every open body and every complete body that still has chunks queued with "fetch failed: egress gateway closed", returns the extents it held while the endpoint is still mapped, unmaps it and keeps serving; a later `fetch()` rejects at once with a TypeError (`worker/egress/fetch_runtime.zig:Refusal`). A chunk that a credit-blocked response parked is the worker's own copy, since parking copies a borrowed extent and returns it to the pool (`worker/serve/response.zig:takeOwnedBytes`), so a response whose fetch body had completed finishes whole across the detach. On the server the channel failure retires the record and wakes the launcher, whose reattach pass spawns a gateway no sooner than `egress_prewarm_interval_ms` after the last spawn and then, one live worker per turn, builds a session on the worker's wake set, writes it into the worker's record and sends the worker's half as an `egress_attach` packet on its control socket (`common/ipc/egress_attach.zig:send`). The record changes first, so no token minted after the attach names the old session. A worker whose socket takes nothing within `launcher.zig:egress_attach_send_timeout_ms`, or whose session the gateway refuses, is retired (`launcher.zig:Deps.retireForEgress`). The worker refuses a half whose liveness pipe is not the one `WorkerInit` brought, compared by device and inode, before it detaches a session it still holds (`worker/egress/state.zig:State.checkAttach`), so a session sent to the wrong worker's socket fails closed; otherwise it maps the half with its boot checks, closes the wake descriptors a detached boot held and polls the ones the half brought from then on. A worker without a grant refuses the attach (`State.attach`).

A worker also detaches on its own, through `worker/egress/gateway_runtime.zig:detachForGatewayFault`, when its completion ring fails its checks, a gateway packet does not decode or contradicts its state, a command write fails, its upload pool breaks or a body-pool release is refused, all of which only a gateway defect produces. The detach settles its fetches and bodies as above and sets `worker/egress/state.zig:State.detached_for_gateway_fault`. The gateway sees only a closed liveness pipe, and the server gives the worker no new session, so the worker asks to be retired: at the top of its next tick it sends `worker_retiring` with reason `egress_detached` (`worker/runtime/retirement.zig`). Its requests in flight finish, a begin decoded after the notice answers 503 `worker_retiring`, and the server retires the worker once no lane holds a slot of it ([request.md](request.md#the-reader-lane-and-forwarding)). A gateway defect therefore retires the workers it touches, while their requests in flight still finish. A detach because the gateway hung up, or because the server sent a new session, asks for nothing.

## A fetch, end to end

1. `worker/host/fetch.zig:collo_runtime_fetch` rejects at once, with a TypeError, a fetch from a worker whose definition has no grant, which answers with the network setting's denial and logs it to the tenant's log, from a detached worker, or for a request whose `DispatchWork` carries `none` (`worker/egress/fetch_runtime.zig:refusal`). `fetch_runtime.zig:schedule` refuses one past `fetches_per_worker_max` counted fetches (`worker/egress/state.zig:State.fetches`, which counts a fetch from its start until the worker reads its body end, its error or the acknowledgment of its stop), past `fetches_per_request_max` started under its token, past `fetch_bodies_per_worker_max` body views, a scheme other than `http:` or `https:`, and a start over the bounds of `common/ipc/egress.zig:checkFetchStart`.
2. `worker/egress/upload_runtime.zig:sendStart` encodes the start with the request's token (`egress.zig:encodeFetchStartInto`). A body up to `fetch_limits.zig:request_body_inline_preferred_bytes_max` rides inline; a larger one is flagged pooled with its total length and streams as upload-pool extents that `egress_upload_chunk_batch` packets announce, each with its running total (`upload_runtime.zig:progressPooledBody`). A pooled start first waits for room in the session's upload reservations, its body's length plus the copies of its start the gateway keeps (`common/ipc/fetch_limits.zig:pooledStartHeldBytes`), so the worker never sends more than the gateway admits in flight.
3. The worker writes the packet into the command ring (`packet_ring.zig:RingView.writePacketReserved`) and wakes the gateway when it may be asleep (`common/ipc/egress_shared/wake.zig:notifyAfterPacketWrite`).
4. The gateway loop drains the session's body-pool releases, then up to `command_flow.zig:command_drain_batch` commands (`egress/gateway/runtime/command_flow.zig:handleCommands`), each copied out with `RingView.readPacket` and decoded from the copy.
5. `command_flow.zig:admitFetchStart` checks, in order, the tag, the token's session against the session whose ring carried it, the clock and the deadline, the session's boot end for a boot token, the policy id against the hello's image, `max_active_fetches_per_worker_session` (the session's fetch records) and `max_active_fetches_per_security_cell` (the fetch table's count for the cell), an unused fetch id in the session, the start's shape (`policy.zig:checkStart`, the same for an inline and a pooled body) and, for a pooled body, the session's upload bytes in flight. Only then does it reserve the fetch's record (`fetch_flow.zig:insert`) and hand the fetch to its shard's engine, or to the upload assembler when it is pooled; a handover that fails ends the record, the one undo. Every refusal fails the fetch with an error packet and leaves the session as it was.
6. `engine.zig:Engine.submit` creates the response queue and the task, stamps the record's handle on the task and submits it with the token's policy and deadline as the fetch's own transport configuration. The engine prepares one plan per hop, which checks the scheme, host and port against the policy before DNS (`egress/client/transport/request/plan.zig`, `request/policy.zig`), and the hop's dial checks every resolved address after it, on each hop and each redirect (`egress/client/engine/dial.zig`): `localhost` names, host bytes the entry grammar cannot read and noncanonical IPv4 literals fail, a resolution with any denied address fails whole, a public address passes under a grant that admits the host, a private one only under a grant with `allowPrivateNetworks` (`common/network/address.zig`), and loopback, link-local, metadata and the other reserved classes never pass.
7. The response returns as completion-ring packets: `egress_fetch_head`, `egress_body_chunk_batch` with body-pool handles and lengths, at most `egress.zig:max_body_chunk_batch_count` chunks, `egress_body_end`, `egress_fetch_error` and `egress_abort_ack`, the first four stamped with the gateway's publish time. An HTTP/2 body arrives still encoded, and the worker decodes it inside its own cgroup within the bounds the head names (`worker/egress/body/decoder.zig`).
8. The worker returns each consumed extent through the body pool's release queue and writes the command eventfd once per batch (`worker/egress/gateway_control.zig:noteBodyPoolChunkReleased`, `flushBodyPoolReleases`). The gateway drains the queue (`egress/gateway/runtime/release_flow.zig:drainReleases`), takes each release's entry from the session's extent ledger (`egress/gateway/sessions.zig:ExtentLedger`), and returns the extent's flow-control credit to the engine of the shard the entry names, whether or not the fetch has ended, unless that shard restarted since the extent was published (`engine.zig:Engine.releaseCredit`). The engine drops a credit whose stream or HTTP/1 fetch has ended, and one worth more than its stream holds.

Every fetch ends in `egress/gateway/runtime/fetch_flow.zig:retire`, which writes its one terminal packet (body end, fetch error or abort ack), lowers the session's and the cell's counts and the session's upload bytes, and frees its record. A fetch the gateway ends while the engine still runs it, a stop, a refused head or a failed publication, is canceled there, and its record waits until the engine lets go of it, settling the task before its head or ending its response queue after it, so a fetch counts against its caps until its terminal packet, canceled ones included. The worker stops a fetch with one `egress_stop` naming its fetch id (`worker/egress/task_runtime.zig:stopFetch`): at most one per fetch, sent when the last view of its body lets go, when its request ends or when the origin's data fails it, and none for a fetch whose terminal packet it already read; a start that never left ends in the worker. The gateway ignores a stop for a fetch it no longer has.

The bytes a fetch moves enter the record of the request that started it as they cross: the inline body or each upload batch once its packet is in the command ring, and each body chunk's length when its packet arrives, whatever happens to the body afterwards (`task_runtime.zig:chargeFetchBytes`). They reach the request's access record as `fetch_sent_bytes` and `fetch_received_bytes`, body bytes only, with no framing, header or TLS byte; a body the gateway forwards still encoded counts its encoded bytes.

On the upload pool the roles swap. The gateway copies each extent into the fetch's assembly buffer, checks the running total against the bytes received, releases the extent at once and wakes the worker (`egress/gateway/runtime/upload_flow.zig:handleBatch`). Once the announced length has arrived, the buffer goes to the engine without a copy (`engine.zig:Engine.submit`'s `owned_body`), and the task keeps it to replay the body on a redirect: a redirect that keeps the body, a 307 or 308, or a 301 or 302 of any method but POST (`egress/client/transport/request/redirect.zig:redirectTarget`), keeps the buffer where it is, with the allocator it came with (`egress/client/task.zig:Task.replaceRequest`), so no hop copies it. A pooled start counts its announced length plus the copies of its start against `fetch_limits.zig:request_body_pooled_in_flight_bytes_max` on both ends, and the buffer and the copies come from the gateway's upload allocator, budgeted at `containment.zig:upload_memory`, never from a shard's. An extent whose running total disagrees fails its fetch; one that arrives after its fetch stopped assembling goes straight back to the pool. An upload still assembling at its token's deadline fails and frees its buffer at the next loop pass (`upload_flow.zig:expire`).

## What each side checks

| Data | Written by | Read by | How | On a contradiction |
| --- | --- | --- | --- | --- |
| command ring | worker | gateway loop | `write_seq` loaded once per packet, the frame header copied and checked once, the packet copied out (`packet_ring.zig:RingView.readPacket`) | ring fatal, session removed |
| commands | worker | gateway loop | decoded from the copy: kind, flags, reserved fields and every length against the packet and `fetch_limits` before any slice (`common/ipc/egress.zig`) | session removed |
| upload slots | worker | gateway loop | one `common/ipc/egress_shared/slot_snapshot.zig:SlotSnapshot`, validated against the pool, sliced from the copy | session removed |
| upload release cursor | gateway, in memory the worker maps writable | gateway | loaded back, checked against `release_read_seq` and its maximum, the entry stored modulo the queue (`body_pool.zig:BodyPoolView.releaseChunk`) | pool fatal |
| body-pool releases | worker | gateway loop | cursors loaded once per drain, each entry copied once and checked against the gateway's own slot (`BodyPoolView.drainReleasedChunksObserved`) and the session's extent ledger | session dropped |
| completion ring read cursor | worker | gateway, as writer | loaded once for space and once after publishing, only to decide on a wake (`RingView.writePacketReserved`) | ring fatal, session dropped |
| completion packets | gateway | worker loop | copied out, decoded with the same checks, ids matched to live tasks and bodies (`gateway_runtime.zig:handlePacketBytes`) | the worker detaches and asks to be retired (`detachForGatewayFault`) |
| body-pool slots | gateway | worker loop | one `SlotSnapshot` per handle (`BodyPoolView.validateChunkRange`) | the worker detaches and asks to be retired |
| token | server | gateway loop | `egress_token.zig:verify` on the decoder's copy | fetch refused |

An extent's bytes stay in shared memory, so a producer can still garble its own bytes after the consumer validated the slot, but it can never move a slice, a length or a cursor. Data the origin controls, such as a body that fails to decode, fails its fetch and never the session (`gateway_runtime.zig`).

## Refusals and removal

A well-formed command that breaks a rule fails only its fetch (`command_flow.zig:Refusal`): a bad tag, another session's token, an unreadable clock, an expired token, an ended boot token, an unknown policy id, either active-fetch cap, a fetch id in use, a start whose shape breaks the limits and full upload bytes each queue an error packet and leave the session as it was, so a refused command allocates nothing and costs the gateway what an accepted one costs. A stop for a fetch the session no longer has is ignored, since a worker cannot see when the gateway ended a fetch. An honest worker presents a bad tag only for requests in flight across a gateway replacement.

The gateway removes the session at once for a command ring that fails its checks, a packet shorter than a kind or of a kind the ring does not carry, a command that does not decode, and an upload extent the pool rejects. It marks the session for drop (`session_flow.zig:markForDrop`) when a packet it writes finds the completion ring full or broken (`session_flow.zig:queuePacket`), when its release drain fails or a release misses the extent ledger, when its rings cannot be measured, and after `hard_drop_grace_ns` at `hard_percent`; marked sessions go at the end of the pass. Each of these is a `protocol_violation`. The server hears of every removal except a failed ack's, with its cause, and retires the worker for a protocol violation ([Sessions](#sessions)).

## Open points

The gateway keeps no count per token, so the per-request fetch limit holds only an honest worker. A worker that keeps tokens after their requests, or spends the token of every request in flight in its process, is bounded by its session's `max_active_fetches_per_worker_session` concurrent fetches and the deadlines of the tokens it holds, up to `common/limits/server.zig:request_timeout_ms_max` after admission, and it reaches every origin any of its tokens' policies admits, the boot token's union of its routes' grants included ([security.md](security.md#open-points)).

The upload budget is shared. Each session holds at most an eighth of it, so eight sessions at their cap, which one definition's pool can hold, make every other session's pooled start fail until their uploads finish or their tokens' deadlines pass (`containment.zig:upload_memory`, `upload_flow.zig`).
